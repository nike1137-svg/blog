먼저 소식 하나. 공모전에서 **생활 속 AI 활용 분야 우수작품**으로 선정됐다.

교육기관 과정을 시작하기 전에 혼자서 만든 작품이다. 어디서부터 해야 할지 몰라 헤맨 날이 많았고, 실수도 정말 많이 했다. 그래도 나름대로 열심히 붙들고 있었던 작품이라, 결과가 좋게 나와서 너무 기쁘다. 이 작품이 **내 도메인을 시니어로 잡은 계기**가 됐다. 그 뒤로 만드는 것들이 자꾸 시니어 쪽을 향하고, 이번 과제의 시니어 건강도 그 길 위에 있다.

그리고 오늘 이야기. 딥리서처 과제 데모를 노트북에서 돌리다가, 집에 있던 **공기계 스마트폰(갤럭시 A51 5G)** 으로 서버를 옮겼다. 과제를 이해하는 데 쓴 시간도 중요하지만, 생각만 하고 해 보지 못한 실험을 제출물에 녹여 내 보고 싶었다.

## 1. 문제 — 데모가 노트북에 매달려 있었다

데모는 노트북에서 서버를 돌리고 Cloudflare 터널로 공개했다. 터널은 서버가 있는 기기가 **밖으로 길을 걸어 두는** 방식이라, 노트북이 꺼지면 길도 끊긴다. 평가자가 주소를 눌렀을 때 열리느냐는 결국 **내 노트북이 켜져 있느냐**에 달려 있었다.

작업 스케줄러로 자동 시작까지 붙였다. 죽으면 10초 뒤 다시 띄우게도 했다. 그래도 윈도우 시스템 기록을 열어 보니 9월 24일 하루에만 이랬다.

| 시각 | 일 |
|---|---|
| 02:07 | 예기치 않은 종료 → 아침에 다시 켤 때까지 약 5시간 꺼짐 |
| 07:32 · 10:58 | 다시 시작 |
| 12:59 | 예기치 않은 종료 → 약 1시간 19분 꺼짐 |
| 22:36 | 전원 끄기 → 약 23분 꺼짐 |

**하루에 적어도 6시간 40분**, 공개 주소가 열리지 않았다. 노트북은 개인 작업용이라 다시 시작하고 끄는 일이 자연히 생긴다. 절전 · 로그인 · 포트 겹침까지 늘 신경 써야 했다.

## 2. 서버가 되려면 넘어야 할 네 고개

「스마트폰으로 띄울 수는 없나」 하고 상상만 하다가, 어떤 기기든 서버가 되려면 뭐가 필요한지부터 정리했다.

| 고개 | 뜻 | 공기계에서 |
|---|---|---|
| ① 계속 켜져 있나 | 기기와 프로그램이 멈추지 않아야 한다 | 충전기에 꽂아 한자리에 둔다 |
| ② 밖에서 찾아올 수 있나 | 집 인터넷은 공유기 뒤라 바로 못 들어온다 | 폰이 밖으로 터널을 건다 |
| ③ 운영체제가 허락하나 | 뒤에서 도는 프로그램을 OS 가 끄지 않아야 한다 | 서버 전용이라 절전을 다 꺼도 된다 |
| ④ 비밀을 어디에 두나 | 터널 토큰이 그 기기에 있어야 한다 | 폰 전용 터널을 새로 만든다 |

내가 들고 다니는 폰이면 ①③ 이 어렵다. 안 쓰는 공기계는 그 폰 하나를 서버로만 둘 수 있어서 사정이 달랐다.

## 3. 폰에 올리기 — 가장 어려운 관문부터

폰에는 **Termux**(안드로이드용 리눅스 환경)를 깔고 파이썬 · git · cloudflared 를 올렸다. 문제는 과제 데모의 패키지였다. 60개 안팎인데 그중 **17개가 속이 C · Rust** 로 되어 있다. PyPI 의 완성본(휠)은 안드로이드용이 아니라서 폰에서 직접 빌드해야 할 수 있다.

자료를 찾아보니 jiter(openai 가 쓰는 Rust 패키지)를 안드로이드에서 빌드하다 실패한 사례가 있었다. 그래서 **jiter 하나만 먼저** 시험했다. 여기서 막히면 뒤는 할 필요가 없으니까.

`pkg install rust` → rustup 이 아니라 Termux 패키지로 러스트 설치
`ANDROID_API_LEVEL=24 pip install --extra-index-url <TUR 저장소> jiter` → 빌드 도구 maturin 은 폰용 완성본을 받고, jiter 는 폰에서 빌드

**1분 10초** 만에 됐다. 실패 사례는 rustup(안드로이드를 지원하지 않음)과 미러 오류가 원인이었고, Termux 의 rust 로는 문제가 없었다. 이어서 패키지 전체를 깔았다. **8분 26초**, 폰에서 빌드한 것은 pydantic-core · orjson · ormsgpack · uuid-utils 등 7개였다.

## 4. 계속 켜 두기 — runit 과 Termux:Boot

노트북에서는 「죽으면 10초 뒤 다시」 반복문을 직접 짰다. 폰에서는 **termux-services** 를 썼다. 속은 **runit** 이라는 서비스 관리자다. 서비스가 끝나면 곧바로 다시 띄우고, 기록도 따로 쌓아 준다.

`$PREFIX/var/service/senior/run` → `exec .venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8080`
`~/.termux/boot/start-services` → `termux-wake-lock` 뒤에 서비스 관리자를 띄우는 부팅 스크립트

알고 가기 — 서비스 관리자는 **넘어진 프로그램을 일으켜 세우는 관리인**에 가깝다. 실제로는 `run` 스크립트가 끝나면 runsv 가 그것을 다시 실행하고, 곧바로 끝났다면 1초 기다렸다 다시 띄운다. 리눅스의 systemd 와 같은 자리다.

작은 발견도 있었다. cloudflared 패키지가 넣어 둔 기본 서비스에는 `exec 2>&1` 이 없다. runit 은 표준 출력만 기록으로 넘기는데 cloudflared 는 표준 오류로 기록을 쓴다. 그래서 기본 서비스를 고치지 않고, 이 줄을 넣은 **내 서비스를 따로** 만들었다.

## 5. 주소 옮기기 — 명령이 엉뚱한 터널을 집었다

평가자에게 이미 알려 준 주소를 그대로 살리고 싶었다. 폰 터널에 경로를 더하고, DNS 를 폰 터널로 옮기면 된다.

`cloudflared tunnel route dns --overwrite-dns a51-phone senior.dodami-ai.com`

그런데 아무것도 바뀌지 않았다. 「이미 이 터널로 가도록 되어 있다」는데, 찍힌 터널 ID 가 **폰 터널이 아니라 노트북 터널**이었다. 노트북의 cloudflared 설정 파일에 `tunnel:` 줄이 있어서, 명령이 내가 적은 이름 대신 그 터널을 집은 것이다. 빈 설정 파일을 주고 **터널 ID 로 직접** 넣어서야 옮겨졌다.

어느 기기에서 답이 오는지는 숫자로 가렸다. 폰은 옛 코드라 재생 목록이 89편, 노트북은 새 코드라 88편이었다. 명령이 「성공」이라고 말해도, **무엇을 바꿨는지는 결과로 확인해야 한다.**

## 6. 검증 — 끄고 켜 보기

| 시험 | 결과 |
|---|---|
| 폰 다시 시작 · Termux 는 열지 않음 | **34초 뒤** 공개 주소가 다시 열림 |
| 서버 · 터널 프로그램을 강제로 끝냄 | **3초 만에** 새로 뜸 (pid 가 바뀜) |
| 폰에서 직접 물어보기 (내 키) | **22초 · 약 23원** — AI 호출까지 폰에서 된다 |
| 노트북 데모 · 터널을 끈 상태 | 평가자 주소로 재생 · 음성 · 결과 모두 정상 |

마지막 줄이 이 실험의 목표였다. **노트북을 꺼도 데모가 열린다.**

## 7. 보안

- 폰은 보안 패치가 2024년 5월에서 멈췄다. 그래서 **공유기 포트는 열지 않고 터널로만** 연다
- 폰에는 터널 토큰 파일 하나만 두고, 스크립트에는 토큰이 아니라 **파일 경로**만 적었다
- 데모 서버는 여전히 **방문자 키로만** AI 를 부른다. 서버에 내 키는 없다

## 8. 회고

8월 말, 다른 과제 챗봇을 노트북으로 공개하던 날 이렇게 적었다 ([내 쪽에서 통과한 것이 상대 쪽에서도 통과하지는 않았다](/blog/posts/passed-on-my-side-not-theirs/)).

> 어딘가에는 항상 켜져 있어야 하는 컴퓨터가 있다.

그때는 그 컴퓨터가 노트북이었다. 한 달 가까이 지나서야 그 컴퓨터가 **집에 있었다**는 걸 알았다.

과제를 끝내는 것과 별개로, 머릿속에만 있던 「폰으로 띄울 수 없나」를 실제로 돌려 본 게 이번에 가장 많이 남는다. 순서도 과제에서 배운 그대로였다. 자료로 먼저 조사하고, 가장 어려운 관문부터 시험하고, 일부러 꺼 보며 정말 스스로 뜨는지 확인했다.

| AI 가 한 일 | 내가 판단 · 검토한 일 |
|---|---|
| 자료 조사 (Termux · 패키지 · 삼성 절전 · 터널) · 명령과 스크립트 초안 · 공개 주소에서 확인 | 노트북 대신 **공기계**로 가자고 정함 · 가장 어려운 jiter 부터 시험하기로 함 |
| 서비스 · 부팅 스크립트 작성 · 기록 정리 | 폰에서 명령을 직접 입력하고 화면으로 결과 확인 · 재시동 · 강제 종료 시험 |
| DNS 명령 실행 · 잘못 집은 터널 원인 찾기 | 평가자 주소를 **그대로 폰으로 옮기기**로 결정 · 노트북 자동 시작을 끄기로 결정 |
