[잠기지 않는 자물쇠](/blog/posts/lock-that-doesnt-lock/)에서, 규칙을 걸어놨는데도 문이 실제로는 잠기지 않았던 일을 적었다. 그때 배운 건 "설정했다"와 "실제로 그렇게 된다"가 다르다는 것이었다. 오늘 맥미니를 로컬 AI 서버로 세우면서 그 교훈을 두 번 다시 만났다 — 한 번은 "설치됐다"가 "GPU로 돈다"를 보장하지 않는다는 데서, 또 한 번은 "서버가 섰다"가 "실제로 쓸 수 있다"를 보장하지 않는다는 데서. 이 맥미니 프로젝트는 [껍데기를 갈아 끼운 날](/blog/posts/wrapper-doesnt-change-the-model/)에서 "준비 중"이라 적어둔 바로 그것이고, 오늘 처음 실물을 세웠다.

## 1. 발단 — 라즈베리파이를 알아보다 결론이 뒤집혔다

시작은 "라즈베리파이가 정확히 뭔지" 궁금해서였다. 그래픽카드처럼 본체에 꽂는 확장 카드인 줄 알았는데, 찾아보니 기판 한 장 자체가 독립된 컴퓨터였다. 이런 걸 SBC(싱글보드 컴퓨터)라고 부른다는 것도 그때 알았다.

쓰임새를 훑어보니 CCTV, 홈서버, 광고 차단 서버, IoT 허브 같은 게 나왔다. 우리 집 시스템에 대입해보니 진짜 필요한 자리가 하나 보였다 — **감시자(watchdog) 노드.** 감시 대상과 감시자가 같은 기계에 있으면, 대상이 죽을 때 감시자도 같이 죽는다는 구조적 문제가 있다. 이 역할은 따로 떼어둘 필요가 있었다.

그런데 여기서 결론이 뒤집혔다. **라즈베리파이를 살 필요가 없었다.** 이미 미개봉 상태의 맥미니 M4 24GB가 집에 있었다. 유휴 전력 차이는 2W뿐인데 처리 성능은 수십 배 차이가 난다. 게다가 지금은 메모리 수급 문제로 라즈베리파이와 미니PC 가격이 정가의 1.5~2배로 뛰어 있었다. 새 장비를 사는 게 아니라 가진 걸 쓰는 게 답이었다.

## 2. 셋업 — 추가 지출 0원

설치를 시작하기 전에 비용부터 확인했다. Ollama, Tailscale, Homebrew 전부 무료이고 과금이 붙는 지점이 없다는 걸 확인한 뒤에 들어갔다. 순서는 이랬다.

1. **macOS 초기 설정** — Apple ID는 로그인하지 않았고, Apple Intelligence는 건너뛰었다. 24GB 메모리를 Ollama가 써야 하는데 이게 옆에서 갉아먹는다. FileVault도 껐다. 켜두면 재부팅할 때마다 사람이 직접 암호를 쳐야 하는데, 그러면 화면 없이 원격으로 돌리려는 목적과 충돌한다. 자동 업데이트는 다운로드까지만 하고 설치는 막았다.
2. **SSH 원격 로그인 켜기** — 오늘의 진짜 관문이었다. 이게 뚫리는 순간 데스크탑 자리의 키보드를 정리하고, 화면 없이 작업할 수 있게 됐다.
3. **Tailscale 합류** — 사설망 안에서만 통하는 고정 주소(`100.65.47.40`)를 받았다. 공유기를 재부팅해도 이 주소는 안 바뀐다.
4. **Homebrew 설치**
5. **Ollama 설치 + `gemma4:12b`(7.4GB) 내려받기**
6. 첫 추론 성공. `ollama ps`로 확인하니 **100% GPU**로 돌고 있었다.

## 3. 오늘 막은 사고 — 설치하기 전에 확인부터

처음엔 그냥 `brew install ollama`로 설치하려 했다. 그런데 설치하기 전에 "지금 기준으로 어떤 방법이 맞는지 먼저 확인하자"고 생각을 바꿨다.

찾아보니 애플 실리콘에서는 **formula(명령줄 도구) 방식으로 설치하면 추론에 필요한 `llama-server` 바이너리가 빠져서, 요청이 500 오류를 내거나 CPU로 조용히 폴백된다**는 버그 리포트가 있었다(Homebrew 저장소, 2026년 6월). 인터넷에 흔히 도는 `brew install --cask ollama` 안내도 낡은 정보였다 — 실제 cask 이름은 어느 순간 `ollama-app`으로 바뀌어 있었다.

> 관련 개념: [껍데기를 갈아 끼운 날](/blog/posts/wrapper-doesnt-change-the-model/)에서는 랭체인으로 겉만 바꿔도 모델이 받는 입력은 똑같았다. 오늘은 정반대였다 — 같은 Ollama, 같은 모델인데 **설치 경로(껍데기)만 다르면 아예 GPU를 못 쓰는 기계가 됐다.**
{: .prompt-info }

그대로 formula로 설치했으면 `library=cpu`로 돌아가는, 맥미니를 산 이유 자체가 없어지는 기계가 됐을 것이다. 실제로 cask로 설치하고 나서 `ollama ps`에 찍힌 `100% GPU`가 그 판단이 맞았다는 걸 숫자로 증명해줬다.

## 4. 알게 된 제약들

- **포트가 없다.** M4 맥미니는 USB-A 포트가 아예 없어서, 무심코 키보드를 꽂으려다 막혔다. 전원 버튼도 뒷면이 아니라 본체 바닥면으로 옮겨져 있었다.
- **24GB는 MLX 가속 대상이 아니다.** 맥미니는 CPU와 GPU가 메모리를 따로 안 쓰고 한 풀을 나눠 쓰는 통합 메모리 구조라, 24GB라는 숫자 하나가 모델 크기의 실질적인 천장이 된다. 애플의 GPU 가속 경로는 두 겹인데, Metal은 24GB에서도 받지만 그 위의 MLX 추가 가속은 32GB 이상을 요구한다. 인터넷에 도는 벤치마크 수치를 그대로 기대하면 안 된다는 뜻이다.
- **모델 크기 한계가 뚜렷하다.** 24GB에서 현실적인 크기는 12~14B 선이다. 70B는 4비트로 압축(양자화)해도 43GB가 필요해서 아예 안 들어간다.
- **`gemma4:12b`는 사고 모드가 기본으로 켜져 있다.** 한 문장짜리 답에도 긴 사고 블록을 먼저 생성한다. 로컬이니 그 사고 토큰에 요금은 안 붙지만, 대신 시간을 깎아먹는다. 예전에 Vertex 쪽에서 사고 모드를 끄니 토큰이 크게 줄어든 걸 본 적이 있는데, 같은 이야기가 여기서는 요금이 아니라 시간의 문제로 다시 나타난 셈이다.
- 작업 중간에 화면이 몇 번 깜박여서 놀랐는데, 원인은 전원 쪽 문제였다. SSH가 이미 열려 있어서 화면 없이도 작업은 끊기지 않고 이어졌다.

## 5. 세웠으면 써봐야 한다 — 사투리 번역으로 한국어 품질 시험

여기까지가 "설치가 됐다"였다. 그런데 설치가 됐다는 것과 실제로 쓸 수 있다는 것은 다른 문제다. 그래서 곧바로 "됐다"고 접지 않고, 이 로컬 모델이 무엇에 쓸 만한지 시험해보기로 했다.

이 프로젝트가 향하는 곳은 고령 가족을 위한 돌봄 대화다. 그렇다면 표준어보다 어려운 말 — 방언과 반어법 — 을 얼마나 알아듣는지가 진짜 시험이다. 마침 음성 쪽은 앞선 실험에서 이미 확인해둔 게 있었다. 클라우드 음성 인식 대신 로컬 Whisper를 썼을 때 오류율이 용인할 수준이면서 속도는 오히려 빨랐고, 비용은 0원에 외부로 나가는 데이터도 없었다. **귀(음성 인식)는 이미 집 안으로 내릴 만하다는 확신이 있었다.** 남은 건 두뇌(대화 생성)였다.

부산 사투리 문장 하나를 골라 표준어로 바꿔보라고 시켰다.

> "어지는 집에서 실라캤더마는 아아들이 어띠기 쫄라쌋는지 큰집에 할무이 뵈러 안 갔더나"

뜻은 이렇다 — *어제는 집에서 (있기) 싫다고 했지만, 아이들이 어찌나 졸라대던지 큰집에 할머니 뵈러 결국 갔다.* 마지막 "안 갔더나"는 형태만 부정문이지 실제로는 갔다는 반어법이다. 같은 문장을 다섯 번 반복해서 물었다.

## 6. 다섯 번 모두, 다른 방향으로 틀렸다

| 회차 | 결과 |
|---|---|
| 1 | 사고만 반복하다 답을 못 냄 |
| 2 | "술을 마셨더니 신이 나서 안 갔더냐" — 뜻도 방향도 반대 |
| 3 | "실례했다마는… 안 갔더나" — 또 다른 오역 |
| 4 | "차려 내어 드렸더니 좋아했는지" — 또 다른 오역 |
| 5 | "술이라 카더마는… 안 갔더라고요" — 술로 회귀, 방향은 계속 반대 |

핵심 단어 "실라캤더마는"(싫다고 했지만)을 매번 다르게 찍었다. 실려·실례·술·차려로 계속 헤맸다. 그리고 "안 갔더나"의 반어법은 다섯 번 다 못 잡고 문자 그대로 "안 갔다"로 읽었다.

여기서 잠깐 이런 생각이 들었다 — *대화를 많이 시키면 학습돼서 나아지지 않을까?* 그런데 그건 오해였다. **로컬 모델은 대화한다고 가중치가 바뀌지 않는다.** 매번 완전히 처음 상태에서 시작한다. 다섯 번이 서로 수렴하지 않고 계속 다른 방향으로 틀린 것이 바로 그 증거다. 학습이 쌓였다면 조금씩 한 답으로 모여야 하는데, 그러지 않았다. 같은 질문에 매번 다른 답이 나온다는 건, 이 지식이 모델 안에 약하게만 들어 있어 추측으로 빈자리를 메우고 있다는 신호였다.

모델을 실제로 바꾸려면 재학습(파인튜닝)이 필요한데 그건 지금 비현실적이다. 현실적인 길은 질문 방식을 다듬는 프롬프트 엔지니어링 쪽이다 — 다만 오늘 결과를 보면, 이 난이도의 방언·반어법은 프롬프트를 손본다고 온전히 잡힐 것 같지도 않다.

**판정**: 이 로컬 모델(`gemma4:12b`)은 이 정도 한국어 뉘앙스에서는 아직 못 미덥다. 음성 인식은 이미 로컬로 될 만하지만, 대화 생성은 표준어보다 어려운 자리에서 신뢰하기 이르다. 그렇다면 방향은 둘 중 하나다 — 표준어 대화로 다시 재보거나, 대화 생성만 클라우드에 남기고 로컬은 음성 인식·요약 같은 주변부부터 맡기는 것.

## 남은 과제

| 항목 | 내용 |
|---|---|
| 표준어 재검증 | 사투리 말고 순수 표준어 대화로, 사고 모드를 끈 채 다시 시험 |
| 컨텍스트 길이 | 기본값 4096 — 확대 필요 |
| 바인딩 범위 | Ollama는 인증 기능이 없어 지금은 `127.0.0.1`로 닫아둠. 인증 없이 공개 노출된 Ollama 서버가 17만 대 발견됐다는 보고가 있어서, tailnet에 열지는 신중히 판단할 것 |
| 재부팅 후 자동 시작 | 아직 확인 안 함 |
| 속도 실측 | tok/s 벤치마크 남음 |

이 순서는 맥미니 로컬 AI 프로젝트 전체의 로드맵과도 맞물린다. 앞서 음성인식(STT)을 로컬로 내렸고, 이제 모델 추론 차례다. 그리고 [껍데기를 갈아 끼운 날](/blog/posts/wrapper-doesnt-change-the-model/)에서 "통째 투입만 확인하고 RAG·just-in-time은 차후로 남긴다"고 정해둔 순서를, 하드웨어 쪽에서도 그대로 따라간다 — 지금은 서버를 세우는 단계이고, RAG는 그다음이다. 오늘 사투리 검증이 못 미더웠던 것도 이 로드맵을 재촉한다. 지식이 약하게 든 모델에 방언까지 맡기려면, 결국 관련 자료를 그때그때 찾아 넣어주는 단계(RAG)가 필요해진다.

## 오늘 내가 판단한 것

| AI가 한 일 | 내가 판단한 일 |
|---|---|
| 설치 명령 안내, 각 설정 항목의 의미 설명 | 라즈베리파이를 사지 않고 가진 맥미니를 쓰기로 한 것 |
| 최신 설치 방법 검색 | **설치하기 전에 어떤 방법을 쓸지 먼저 확인하자고 한 것** — 이게 설치 사고를 막았다 |
| 사투리 번역 결과 정리 | 셋업이 끝났다고 접지 않고 실제로 써보며 검증하기로 한 것 |
| — | 같은 문장을 다섯 번 물어 "우연히 틀렸다"가 아니라 "매번 다르게 틀린다"는 패턴을 잡아낸 것 |
| — | "대화하면 모델이 똑똑해지지 않냐"는 생각을 스스로 던지고, 그게 오해였음을 확인한 것 |

오늘 배운 건 두 겹이다. 하나, 설치 방법을 확인하지 않고 익숙한 명령을 쳤으면 아무 오류 없이 설치가 끝난 뒤에야 GPU를 못 쓰는 걸 알았을 것이다. 둘, 서버를 세운 것과 그 서버가 쓸 만한 것은 완전히 다른 문제였고, 다섯 번 물어보지 않았으면 "한 번 틀렸네" 하고 넘어갈 뻔했다. 다음은 사투리를 걷어내고 표준어 대화로, 사고 모드를 끈 채 다시 재보는 것부터다.
