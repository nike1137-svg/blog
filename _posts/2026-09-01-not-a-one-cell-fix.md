## 1. 클론과 VS Code는 고르는 게 아니었다

나는 GitHub에서 클론해서 실습할 생각이었다. 그런데 강사님은 VS Code를 권했다. 둘 중 하나를 고르는 건 줄 알았다.

아니었다. **층이 다른 일이다.**

```
GitHub          인터넷에 있는 원본
   ↓ git clone
내 컴퓨터 폴더    파일이 실제로 놓인 곳
   ↓ 열기
VS Code         그 폴더를 보고·고치고·실행하는 도구
   ↓ 커널 선택
.venv 파이썬     실제로 코드를 돌리는 쪽
```

클론은 **가져오는 일**이고 VS Code는 **가져온 걸 여는 도구**다. 순서대로 하는 일이지 대체 관계가 아니다. 클론해 놓고 열 도구가 없으면 폴더만 있는 셈이다.

> **알고 가기** — VS Code 안에 Git이 들어 있다. 클론한 폴더를 열면 왼쪽에 소스 제어 패널이 생기고, `git status`나 `git diff`를 터미널에 치지 않아도 뭐가 바뀌었는지 보인다. 둘이 따로 노는 게 아니라 붙어 있다.

VS Code는 처음 써 봤다. 설치하고 나서 두 가지에서 걸렸다. 하나는 **제한 모드(Restricted Mode)** — 처음 여는 폴더의 코드를 함부로 실행하지 않는 상태라, 이걸 풀지 않으면 셀이 돌지 않는다. 다른 하나는 **커널 선택**이다. 이걸 전역 파이썬으로 잡으면 방금 설치한 패키지를 하나도 못 찾는다. 뒤에 나오는 모든 게 여기서 갈린다.

## 2. 강사님이 준 노트북만으로는 안 돌아갔다

디스코드로 받은 노트북을 열고 위에서부터 돌렸다. 단어 목록을 읽는 셀에서 멈췄다.

```
FileNotFoundError: banned_phrases.txt
```

노트북 혼자로는 안 되는 거였다. 같은 폴더에 있어야 할 파일 셋(`requirements.txt`, `banned_phrases.txt`, `desired_phrases.txt`)이 없었다.

**클론해 둔 저장소에 그게 다 있었다.** 저장소를 받아 놓기만 하고 열지 못하던 게, 여기서 값을 했다. 노트북을 저장소의 해당 예제 폴더 안으로 옮기니 경로가 맞았다.

다만 저장소 원본 노트북과 강사님이 준 노트북은 모델이 달랐다. 원본은 접근 신청이 필요한 모델이고, 강사님 쪽은 신청 없이 쓸 수 있는 작은 모델로 바뀌어 있었다. 그래서 **부속 파일은 저장소 것, 노트북은 강사님 것**으로 합쳤다.

## 3. 오류는 파일을 가리켰지만 원인은 내 운영체제였다

파일을 맞춰 놓고 다시 돌렸더니 이번엔 다른 데서 멈췄다.

```
UnicodeDecodeError: 'cp949' codec can't decode byte 0xe2
```

메시지만 보면 파일이 깨진 것 같다. 아니었다. **파일은 UTF-8인데 한국어 윈도우의 기본 인코딩이 `cp949`라서**, 파이썬이 cp949로 읽으려다 실패한 것이다. 실제로 확인해 보니 그 파일에 ASCII가 아닌 바이트가 아홉 개 있었다. 특수문자 몇 개 때문에 전체가 멈춘 셈이다.

강사님 화면에서는 이 오류가 안 난다. Mac은 기본이 UTF-8이다.

> **알고 가기** — 인코딩은 글자를 숫자로 바꾸는 약속이다. 쓸 때와 읽을 때 약속이 다르면 같은 숫자를 다른 글자로 읽는다. 파일이 상한 게 아니라 **읽는 방식이 안 맞은 것**이다.

8월 13일에 [내가 쓴 설명서는 나만 따라갈 수 있었다](/blog/posts/my-manual-only-worked-for-me/)를 썼다. 그때 적은 문제는 이거였다.

> 내 기계에서는 되는 게 왜 남에게는 안 되는지

오늘은 방향이 반대였다. **남의 기계에서는 되는 게 내 기계에서 안 됐다.** 같은 모양의 문제인데 내가 반대편에 서 봤다. 그때는 내 설명서에 빠진 단계가 원인이었고, 오늘은 운영체제 기본값이 원인이었다.

## 4. 땜질과 이전 사이에서 이전을 골랐다

고치는 방법은 세 가지였다.

| 방법 | 범위 | 대가 |
|---|---|---|
| 셀마다 `encoding="utf-8"` 추가 | 그 셀만 | 예제마다 매번 반복 |
| 환경변수를 파일로 걸어 저장소 안에서만 UTF-8 | 저장소 안 | 교재 코드는 그대로 |
| WSL로 옮기기 | 전부 | 처음부터 다시 세팅 |

첫 번째가 제일 빨랐다. 그런데 저장소에 예제가 **32개**였다. 한 번 고치고 끝날 일이 아니라, 앞으로 계속 같은 자리에서 같은 오류를 만나는 구조였다. 게다가 교재 원본 코드를 매번 손대야 한다.

WSL은 기본 인코딩이 UTF-8이다. **교재 코드를 한 글자도 안 고쳐도 그대로 돌아간다.** 세팅을 다시 하는 시간은 들지만 그다음부터는 이 문제가 없다.

옮기고 나서 확인해 보니 교재 원본 그대로 파일이 읽혔다. 금지어 목록 412줄, 권장어 목록 38줄. `encoding=`을 붙인 곳은 한 군데도 없다.

## 5. 옮기고 나서 세 번 더 막혔다

이전이 끝이 아니었다. 두 번째 예제 폴더를 준비하는데 세 군데서 걸렸다.

**하나.** 어떤 패키지가 파이썬 3.13용으로 미리 빌드된 게 없어서, 설치하려면 Rust 컴파일러를 요구했다. 그 폴더만 파이썬 3.12로 가상환경을 만들어 해결했다. → 폴더마다 파이썬 버전이 달라도 된다는 걸 이때 알았다.

**둘.** 모델을 부르는데 이름이 정의되지 않았다는 오류가 났다. 교재의 `requirements.txt`에 `accelerate`가 빠져 있었다. 직접 설치하니 지나갔다.

**셋.** 다른 라이브러리 하나가 최신 버전에서 제거된 모듈을 참조하고 있었다. 버전을 낮춰 맞췄다.

셋 다 교재가 알려주지 않은 것들이다. 목록에 적힌 대로 깔았는데도 안 되는 경우가 있다는 걸 봤다. **`requirements.txt`가 그 환경에서 검증된 목록이지, 모든 환경에서 완전한 목록은 아니다.**

## 6. 모델이 메모리에 안 들어갔다

교재가 지정한 모델을 받기 전에 크기를 먼저 확인했다.

```
모델 가중치      7.64 GB
내 노트북 가용 RAM 7.2 GB
```

받아 봐야 로딩에서 죽는다. 물리 RAM이 8GB라 늘릴 방법도 없다.

그런데 이 예제가 가르치려는 건 **문법 제약(grammar constraint)** — 모델이 다음 토큰을 고를 때 정해진 형식을 벗어나지 못하게 막는 기법이다. 이건 특정 모델에 묶인 개념이 아니다. 그래서 훨씬 작은 모델로 바꿔서 돌려 봤다.

```
모델 로딩       3.9초
문법 제약 생성   6.6초 (25토큰)
```

결과도 문법을 지켰다. **모델을 바꿔도 실습이 성립한다는 걸 확인하고 나서** 노트북의 모델 이름을 고쳤다. `git`이 추적하고 있으니 되돌리는 건 한 줄이다.

여기서 어제 정리한 용어가 걸렸다. 어제 용어정리에 **로짓**을 세 번째로 다시 실으면서 이렇게 적었다.

> 로짓은 "아직 정리되지 않은 중간값"이다. (…) 완성된 것은 기억에 남는데, 완성되기 전 단계는 이름을 붙여도 자꾸 흘러내린다.

오늘 준비한 교재 첫 장의 주제가 **Logits Masking**이다. 그 흘러내리던 중간값을 붙잡아서 특정 단어의 점수를 깎고 올리는 기법이다. 세 번을 물어야 했던 개념이 바로 다음 날 실습 대상으로 나왔다. 아직 예제를 다 돌려 보진 못했지만, 적어도 **왜 그 단계를 건드리는지는 알고 시작한다.**

## 7. GPU가 없다는 게 숫자로 나왔다

내 노트북에는 NVIDIA GPU가 없다. 알고는 있었는데 그게 어느 정도인지는 재 본 적이 없었다.

| 측정 | 결과 |
|---|---|
| 생성 속도 (0.8B 모델) | 0.64 토큰/초 |
| torch 스레드 4 → 8 | 94초 → **228초** |

두 번째 줄이 뜻밖이었다. 스레드를 늘렸는데 **2.4배 느려졌다.** 물리 코어가 4개뿐이라 8개로 나누면 서로 자리를 다투게 된다. 기본값이 이미 최적이었고, 손대지 않는 게 맞았다.

첫 줄로 계산하면 교재 예제에서 문장 하나 만드는 데 몇 분씩 걸린다. 화면은 멈춘 것처럼 보인다. 앞 글에서 12분을 기다렸던 것과 같은 상황인데, 이번엔 **미리 재 놨으니 멈춘 게 아닌 줄 안다.**

## 8. 오늘 한 건 실습이 아니라 준비다

분명히 해 두자면 **교재 예제를 끝까지 돌린 게 아니다.** 셀 몇 개를 돌려 환경이 맞는지 확인한 정도고, 실습 자체는 시작 지점에 서 있다.

대신 다음부터 안 막힐 것들이 정리됐다.

- 인코딩 — WSL로 옮겨서 사라졌다
- 부속 파일 — 저장소를 클론해 뒀으니 예제 32개가 전부 있다
- 의존성 — 폴더마다 가상환경을 따로 두고, 빠진 건 채웠다
- 모델 — 메모리에 들어가는 것으로 바꿔 놓고 동작을 확인했다

그리고 이걸 왜 이렇게 했는지 **저장소 안에 노트로 남겼다.** 폴더마다 파이썬 버전이 왜 다른지, 어떤 패키지를 왜 추가했는지, 모델을 왜 바꿨고 어떻게 되돌리는지. 오늘의 나는 아는데 다음 주의 나는 모를 것들이다.

## 오늘 내가 판단한 것

| AI가 한 일 | 내가 판단한 것 |
|---|---|
| 명령 실행, 오류 메시지 해석 | **클론과 VS Code가 대체 관계가 아니라는 걸 확인한 것** — 헷갈리는 채로 넘어가지 않고 물었다 |
| 인코딩 해결책 세 가지를 정리 | **땜질 대신 이전을 고른 것** — 예제가 32개라 한 번 고치고 끝날 일이 아니라고 봤다 |
| 환경변수를 계정 전체에 거는 방법을 제안 | **"다른 파이썬 작업에도 영향이 있는 거 아니냐"고 되물은 것** — 그 뒤에 범위를 좁힌 방법이 나왔다 |
| WSL 세팅, 패키지 설치, 모델 다운로드 | **어디까지 맡기고 어디부터 내가 할지 그은 것** — 셀 실행과 커널 선택은 직접 했다 |
| 유료 API가 필요한 예제 목록을 조사 | **거기서 멈춘 것** — 결제가 필요한 건 오늘 손대지 않기로 했다 |
| 정리 대상 파일 목록 제시 | **VS Code 본체는 지우면 안 된다는 걸 확인하고 지운 것** |

오늘 새로 안 건 개념이 아니라 **경계**였다. 클론과 편집기, 저장소와 가상환경, 교재가 준 목록과 내 환경이 실제로 요구하는 것 — 각각 어디까지가 어디인지가 오늘 좀 더 또렷해졌다.

그리고 하나 더. 인코딩을 고치는 방법으로 처음 받은 건 **계정 전체에 환경변수를 거는 것**이었다. 그대로 갔으면 앞으로 모든 파이썬 작업의 기본값이 바뀌었을 것이다. 범위가 넓지 않냐고 되물으니 저장소 안으로 한정하는 방법이 나왔고, 결국은 WSL로 갔다. **앞 글에서 네 번 있었던 일이 오늘도 있었다.** 자신 있게 오는 제안이라고 그 범위까지 맞는 건 아니었다.

**다음은** 준비만 해 둔 예제를 실제로 돌려 볼 차례다. 오늘은 환경이 맞는지만 확인했으니, 이제 패턴을 하나씩 끝까지 돌려서 로짓 마스킹이 생성되는 문장을 실제로 어떻게 바꾸는지 눈으로 보는 일이 남았다.
