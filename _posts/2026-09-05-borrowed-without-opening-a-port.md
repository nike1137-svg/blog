어제 [여섯 명이 같은 서류를 읽었다](/blog/posts/six-read-the-same-paper/)를 닫으면서 **"다음은 회의실을 실제로 고칠지 정하는 일"**이라고 적어뒀다. 오늘 한 건 그게 아니다. 어제는 공가라 수업에 못 들어갔고, 그 하루치가 그대로 남아 있었다.

빠진 수업을 혼자 따라가는 게 오늘 할 일이었다. 그런데 앞쪽은 문법 문제였는데 뒤쪽으로 갈수록 기계 문제가 됐다. 결국 오늘 제일 오래 붙잡은 건 파이썬이 아니라 **어느 기계가 모델을 돌릴 것인가**였다.

## 1. 무엇을 따라갔나

수업은 세 갈래였다.

| 갈래 | 내용 |
|---|---|
| 문법 | 조건문 → 반복문 → 반복문에서 빠져나오기 |
| 모델 | 로컬 모델을 파이썬에서 불러 대화하기 |
| 크롤링 | 브라우저를 코드로 몰아 페이지 읽기 |

문법은 웹에서 도는 파이썬 셸로 했다. 브라우저 안에서 파이썬이 돌기 때문에 아무것도 설치하지 않고 한 줄씩 쳐볼 수 있다.

여기서 시간을 꽤 까먹었다. 문법이 어려워서가 아니라 **셸에서 여러 줄짜리 블록을 입력하는 방법** 때문이었다. 계속 프롬프트가 나온 뒤에 들여쓰기를 직접 쳐야 하는데, 자동으로 들어가는 줄 알고 몇 번을 다시 쳤다. 파이썬은 들여쓰기 자체가 문법이라 띄어쓰기 하나가 틀리면 문장이 성립하지 않는다.

## 2. 출구가 없으면 안 멈춘다

반복문에서 알고 간 게 하나 있다.

```python
num = 1
while num <= 5:
    print(num)
    num = num + 1
```

여기서 마지막 줄을 빼면 어떻게 되냐고 물었을 때, 나는 "아무것도 안 나온다"고 답했다. 틀렸다. **`1`이 끝없이 쏟아진다.**

`while`은 조건을 확인만 하고 변수는 건드리지 않는다. 변수를 바꾸는 건 안쪽 코드가 할 일이다. 그게 없으면 조건은 영원히 참이다. 반복문에는 시작값·조건·**변화** 세 개가 있어야 하는데, 빠뜨리는 건 거의 항상 세 번째다.

그다음이 `break`다. `while True:`는 조건이 늘 참이라 스스로는 절대 안 멈춘다. `break`가 유일한 출구다. 이 구조를 알고 나니 뒤에 나온 챗봇 코드가 왜 그 모양인지 바로 읽혔다.

## 3. 기억은 모델이 아니라 리스트에 있다

챗봇은 `while True` + `break` 골격에 모델 호출을 얹은 것이다.

```python
messages = []

while True:
    user_input = input('나: ')
    if user_input == '종료':
        break
    messages.append({'role': 'user', 'content': user_input})
    response = client.chat(model='gemma4:12b', messages=messages)
    answer = response['message']['content']
    print('AI:', answer)
    messages.append({'role': 'assistant', 'content': answer})
```

핵심은 `messages`다. **모델은 앞의 대화를 기억하지 않는다.** 매번 이 리스트 전체를 통째로 보내기 때문에 문맥이 이어지는 것처럼 보인다. 내 말을 넣고, 모델 답도 넣는다. 둘 중 하나만 넣으면 다음 턴에 반쪽만 기억한다.

"나는 마커스라고 해" 다음에 "내 이름이 뭐라고?"를 물어서 확인했다. 리스트가 하는 일이 눈에 보이는 건 이 두 줄이면 충분했다.

## 4. 100% CPU — 7월에 이미 적어둔 값

노트북에서 돌리자 1분이 지나도 답이 안 왔다. 상태를 봤다.

```
NAME          SIZE      PROCESSOR    CONTEXT
qwen3.5:2b    2.4 GB    100% CPU     4096
```

`100% CPU`. 모델 크기를 3분의 1로 줄여도 똑같이 느렸다. 그래서 그래픽카드를 확인했더니 **Intel 내장 그래픽뿐**이었다. Ollama는 NVIDIA·AMD 전용 그래픽만 가속한다. 설정으로 고칠 수 있는 게 아니라 이 기계의 한계였다.

그런데 이건 오늘 처음 안 게 아니다. 7월 28일 글([숫자가 맞아떨어지던 순간](/blog/posts/numbers-that-matched/))에 이미 표로 적어뒀다.

> | GPU | 없음 (내장 그래픽만, 딥러닝 가속 불가) |
> | 모든 모델의 처리 방식 | 100% CPU |

같은 글 끝에 이렇게도 써뒀다.

> 맥미니는 8월 26일에 픽업이다. M4에 통합 메모리 24GB. 오늘 잰 숫자로 계산해보면 거기서는 **12B급까지 여유롭고**, 조건을 맞추면 26B급도 시도해볼 만하다.

그러니까 오늘 노트북에서 잰 건 몰라서 다시 잰 게 아니다. **교육기관 실습은 노트북에, 개인프로젝트는 리눅스 데스크탑과 맥미니에** 두기로 해뒀다. 수업 기록이 한 기계에 모여 있어야 나중에 찾을 수 있어서다. 느릴 걸 알면서도 노트북에서 시작한 이유가 그거고, 오늘 잰 값은 7월 기록을 되풀이한 게 아니라 **그 한계가 수업 환경에서도 그대로인지 확인한 것**이다.

문제는 그다음이었다. 분리를 지키면서 12B를 돌릴 방법이 있는가.

## 5. 그런데 터미널은 왜 빨랐나

맥미니에 붙고 나서(붙은 과정은 다음 절이다) 이상한 게 있었다. 맥미니 터미널에서 `ollama run`으로 물으면 바로 답이 흐르는데, 같은 모델을 내 `chat.py`로 부르면 한참 조용했다.

여기서 걸렸다. **모델이 같고 기계도 같다.** 그러면 남는 건 내 코드뿐이다.

짚이는 게 하나 있었다. 파이썬에서 부를 때 쓰는 `chat()`은 기본값이 `stream=False`다. **답이 다 만들어질 때까지 기다렸다가 통째로 준다.** 터미널은 글자가 생기는 대로 흘려보낸다. 그래서 실제로는 같은 시간인데 하나는 기다림이고 하나는 정적인 게 아닐까.

추정으로 두면 그냥 그럴듯한 이야기다. 그래서 쟀다. 같은 질문, 같은 모델, 3회씩. 답 길이가 매번 달라지니 총 시간만으로는 비교가 안 돼서 **초당 글자수**를 같이 봤다.

| | 첫 글자까지 | 총 시간 | 초당 글자수 |
|---|---|---|---|
| `stream=False` | **48.5초** | 48.5초 | 3.6자 |
| `stream=True` | **0.6초** | 51.0초 | 3.5자 |

세 가지가 읽혔다.

**처리량은 같다.** 초당 3.6자와 3.5자는 구분되지 않는다. 스트리밍은 빠르게도 느리게도 만들지 않는다. 총 시간 2.5초 차이는 그날 답이 몇 자였느냐에서 온 것이다.

**0.6초가 세 번 다 똑같았다.** 이게 제일 인상적이었다. 총 시간은 41.3초에서 57.0초까지 8초씩 흔들리는데 첫 글자만은 0.6, 0.6, 0.6이다. 우연히 비슷한 게 아니라 **답 길이와 무관한 값**이라는 뜻이다.

**그리고 81배.** 48.5초와 0.6초. 내가 "느리다"고 느낀 것의 정체가 이 숫자였다.

여기까지가 데이터가 말하는 전부다. 스트리밍이 "더 빠르다"가 아니라 **"보이기 시작하는 시점이 81배 빠르다"**이다. 둘은 다른 말이다. 어제 글에서도 같은 선을 그었다.

> **"B가 낫다"고 쓰지 않았다.** 데이터가 말하는 건 "구분되지 않는다"까지다. 그 이상은 내가 보태는 말이다.

느린 줄 알았던 게 안 보였던 것이었다. 고칠 대상은 모델도 기계도 아니고 **출력 방식**이었다.

## 6. 포트를 열 것인가 — 거부하고 터널로

맥미니에 붙으려니 연결이 안 됐다. Ollama는 기본적으로 `127.0.0.1`, 즉 자기 자신만 받는다. 다른 기기에서 오는 요청은 집 네트워크든 뭐든 전부 "바깥"으로 취급해 거부한다.

해결책으로 나온 게 수신 주소를 `0.0.0.0`으로 바꾸는 것이었다. 이건 7월 16일에 정리해둔 개념 그대로다.

> 그걸 `127.0.0.1`로만 열면 내 컴퓨터 안에서만 보이고, `0.0.0.0`으로 열면 같은 네트워크 전체에 열린다. **같은 포트라도 어디에 여느냐가 정반대**라는 걸 그때 직접 확인했다.

안 하기로 했다. 실습 하나 하자고 상시로 열어두는 설정을 넣는 게 걸렸다. 8월 16일에 [창을 하나씩 닫으면서](/blog/posts/closing-open-windows/) 내린 결론이 **"혼자 쓰는 도구는 안뜰 쪽으로"** 였는데, 오늘 그걸 되돌리는 셈이 된다.

대신 SSH 터널을 썼다.

```
ssh -L 11500:127.0.0.1:11434 marcus@<맥미니>
```

> **알고 가기 — SSH 터널**
> 포트를 바깥으로 여는 게 아니라, 이미 뚫려 있는 SSH 연결 **안쪽으로** 통신을 태워 보낸다. 요청이 맥미니에 도착할 때는 맥미니 자신이 부른 것처럼 보인다. 그래서 `127.0.0.1`만 듣고 있어도 받아준다. 설정은 하나도 안 바뀐다.

여기서 두 번 헤맸다.

**첫 번째** — 터널을 걸었는데 응답이 이상했다. 맥미니에 있어야 할 모델 대신 노트북 모델이 나왔다. 노트북에서도 Ollama가 같은 번호를 이미 쓰고 있어서 터널이 밀린 것이다. 노트북 쪽 번호만 `11500`으로 바꿔 비켰다.

**두 번째** — 번호를 바꿨는데도 연결이 안 됐다. 확인해보니 **이미 맥미니에 들어가 있는 창에서 다시 맥미니로 SSH를 걸고 있었다.** 터널이 노트북이 아니라 맥미니 안에 생겼다. 프롬프트가 어느 기계인지 안 보고 명령을 친 탓이다.

빠져나와서 노트북 프롬프트에서 다시 걸자 붙었다. 같은 대화가 8초 만에 돌아왔다.

여기서 지킨 게 하나 더 있다. **실습을 맥미니로 옮긴 게 아니라 계산만 빌렸다.** 코드도 파일도 노트북에 그대로 있고, 무거운 부분만 터널 건너에서 돈다. 창을 닫으면 원래대로다. 기계를 나눠 쓰기로 한 규칙을 깨지 않으면서 12B를 쓰는 방법이 이거였다.

## 7. robots.txt — 확인했더니 하지 말아야 할 일이었다

크롤링 과제에는 조건이 하나 붙어 있었다. **먼저 `robots.txt`를 확인할 것.**

대상 사이트의 규칙을 읽었다.

```
User-agent: *
Disallow: /
```

`*`는 모든 봇, `/`는 전체 경로. 예외로 열린 건 소셜 미디어 봇 둘뿐이고, AI 학습 목적은 따로 이름을 적어 막아뒀다. **전면 금지였다.**

그러니까 과제의 정답은 "코드를 잘 짜는 것"이 아니라 **"여기서는 하지 않는 것"**이었다. 확인을 건너뛰고 코드부터 짰다면, 잘 도는 코드를 만들어놓고 금지된 곳을 긁고 있었을 것이다.

순서가 결과를 바꿨다. 이게 오늘 크롤링에서 배운 전부다.

## 8. 그래서 연습은 연습용 사이트로

크롤링 연습용으로 공개된 사이트가 따로 있다. 거기 `robots.txt`는 404였다 — 규칙 파일이 없으니 제한이 없다는 뜻이다. 없다는 것도 확인해야 아는 것이라 똑같이 열어봤다.

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.goto('https://quotes.toscrape.com/')
    for q in page.query_selector_all('.quote'):
        print(q.inner_text())
    browser.close()
```

브라우저를 코드가 대신 열고, `class="quote"`인 덩어리를 전부 골라 글자만 꺼낸다. 명언 열 개가 나왔다.

여기서도 실수가 하나 있었다. 파일을 만드는 명령이 두 번 연속 실패해서 빈 파일이 생겼다. 실행해도 아무 반응이 없어서 코드가 잘못된 줄 알았는데, 열어보니 아무것도 안 들어 있었다. **출력이 없을 때는 코드를 보기 전에 파일부터 열어보는 게 맞다.**

## 9. AI가 한 일 vs 내가 판단한 일

| AI가 한 일 | 내가 판단·검토한 일 |
|---|---|
| 코드 초안과 명령어 제시 | 어느 기계에서 돌릴지 정한 것 |
| 원인 추정 제시 | 그 추정을 그대로 안 쓰고 재보기로 한 것 |
| 측정 스크립트 작성 | 무엇을 재야 비교가 되는지 정한 것 |
| 오류 메시지 해석 | `0.0.0.0`을 열지 않기로 한 것 |
| 크롤링 코드 작성 | `robots.txt`를 먼저 확인한 것 |

### 오늘 내가 판단한 것

- **포트를 열지 않았다.** 실습 하나 때문에 상시 설정을 바꾸는 건 비용이 반대다. 터널은 창을 닫으면 같이 사라진다.
- **추정을 재봤다.** "스트리밍 때문일 것"까지는 AI가 말했다. 그대로 썼으면 그럴듯한 이야기로 끝났을 것이다. 3회씩 재고 나서야 81배가 나왔다.
- **초당 글자수로 봤다.** 답 길이가 매번 다르니 총 시간만으로는 비교가 안 된다. 이걸 안 정했으면 2.5초 차이를 스트리밍 탓으로 읽을 뻔했다.
- **금지된 사이트를 긁지 않았다.** 코드는 이미 짤 수 있었다. 짜지 않기로 한 게 오늘의 결정이다.
- **실습을 옮기지 않았다.** 맥미니가 빠르다고 거기로 작업을 통째로 넘기면 수업 기록이 두 기계로 흩어진다. 계산만 빌리고 파일은 노트북에 뒀다.
- **틀린 예측을 지우지 않는다.** 반복문에서 "아무것도 안 나온다"고 답한 건 틀렸다. 틀린 자리를 남겨둬야 다음에 안 틀린다.

오늘 결정의 절반은 "무엇을 안 했는가"였다. 포트를 안 열었고, 금지된 곳을 안 긁었고, 실습을 안 옮겼다. **셋 다 할 줄 몰라서가 아니라 하지 않기로 정한 것**이라 적어둔다.
