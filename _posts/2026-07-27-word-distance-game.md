> 관련 개념: [오늘의 용어 정리 — AI·머신러닝·딥러닝, 가중치부터 텐서까지](/blog/posts/terms-ai-learning-basics/) — 여기 정리해 둔 **벡터**가 오늘 실습의 재료다. 단어 하나가 숫자 한 줄로 바뀌는 데서 이 게임이 시작된다.
{: .prompt-info }

지난 며칠은 모델을 *어디서* 돌릴지가 고민이었다. 내 방 리눅스, 곧 올 맥미니. 오늘은 질문이 안쪽으로 한 칸 들어왔다 — 모델은 대체 단어를 **어떻게** 이해하는가. 강의에서 언어의 어려움을 짚었다. 사진은 한 장이 통째로 주어지지만, 문장은 단어가 하나씩 순서대로 흐른다는 것. 그런데 그 '순서' 이야기로 들어가기 전에, 나한테 먼저 걸리는 게 있었다. 컴퓨터는 애초에 '고양이'라는 글자를 어떻게 계산 가능한 무언가로 바꾸는 걸까. 답은 생각보다 단순했다 — **단어마다 숫자 한 줄을 붙여준다.** 그리고 단어가 숫자가 되는 순간, 두 단어 사이의 '뜻이 얼마나 가까운가'가 **잴 수 있는 거리**가 된다. 이걸 노트에 문장으로만 남기기 싫어서, 손으로 만져보려고 작은 게임을 하나 만들었다.

## 1. 단어가 좌표를 얻는다

핵심 개념부터 내 식으로 정리하면 이렇다. 아주 넓은 지도가 하나 있고, 단어마다 그 위에 점을 하나씩 찍는다고 보면 된다. 뜻이 비슷한 단어는 점도 가깝게, 상관없는 단어는 멀리 찍힌다. '바다'와 '파도'는 이웃사촌이고, '바다'와 '노트북'은 지도 반대편에 떨어져 있는 식이다. 이 '점의 좌표'가 바로 벡터다.

그럼 두 점이 얼마나 가까운지는 어떻게 재나. 여기서 쓴 게 **코사인 유사도**다. 두 점을 원점에서 화살표로 잇고, 두 화살표가 얼마나 같은 방향을 보는지 각도로 잰다고 생각하면 편하다. 방향이 딱 겹치면 1, 아무 상관 없으면 0에 가깝다. 거리가 아니라 '방향'을 본다는 게 처음엔 낯설었는데, 문장 길이 같은 것에 안 휘둘리고 '뜻의 결'만 보려는 장치라고 이해했다.

## 2. 게임의 뼈대

규칙은 단순하다. 정답 단어를 하나 몰래 정해두고, 사용자가 단어를 던지면 정답과의 코사인 유사도를 계산해 점수와 순위를 돌려준다. 꼬맨틀(Semantle)이라는 게임을 한국어로 흉내 낸 셈이다.

재료는 세 가지였다.

- **모델**: `paraphrase-multilingual-MiniLM-L12-v2`. 여러 언어를 한 지도 위에 같이 올려주는 다국어 모델이라 한국어 단어도 벡터로 바꿔준다.
- **장치**: CPU 전용으로 못 박았다. 그래픽카드가 없어도 돌아가야 내 환경에서 의미가 있다.
- **계산**: 후보 단어를 한꺼번에 벡터로 바꾸고, 정답 벡터와의 코사인 유사도로 줄을 세운다.

여기까지는 개념이 코드로 그대로 옮겨진 거라 막힘이 없었다.

## 3. 돌려보니 점수가 한곳에 뭉쳤다

문제는 실제로 플레이할 때 드러났다. 완전히 엉뚱한 단어(정답이 '바다'인데 '노트북')만 빼면, 나머지 점수가 죄다 30~40점 언저리에 몰려 있었다. '사랑' 36점, '여행' 36점, '음악' 37점… 이러면 누가 더 가까운지 감이 안 온다. 다국어 임베딩이 유사도를 좁은 구간에 압축해서 뱉는 특성 탓이었다.

그래서 두 가지를 손봤다.

1. **점수 재보정**: 후보들의 최저~최고 유사도를 0~100으로 쭉 펴줬다. 제일 먼 단어가 0, 제일 가까운 단어가 100이 되게 만드니 순위 차이가 점수로 확 벌어졌다.
2. **순위 힌트 + 웜/콜드**: '몇 점'만으로는 부족해서, '후보 49개 중 몇 위'인지를 항상 붙였다. 여기에 내 최고 기록과 비교해 "지금까지 중 가장 가까워요 🔼 / 최고 기록엔 못 미쳐요 🔽"를 얹으니, 그제야 방향을 좁혀가는 맛이 났다.

그 힌트를 붙이고 직접 한 판 돌려봤다. 정답이 무엇인지 모른 채 '고구마 → 고인돌 → 도서관 → 콘서트…' 를 던지며 웜/콜드를 따라 좁혀갔고, 열 번째 추측에서 정답 '고양이'를 찾았다. 이 글의 제목은 거기서 나왔다.

## 4. 모델이 가끔 엉뚱하다

그런데 고쳐도 남는 벽이 있었다. 정답이 '음악'일 때 '포도'가 3위로 튀어나왔다. 뜻으로는 아무 관계도 없는데. '겨울'의 '눈'과 신체의 '눈'을 구분 못 해서 엉뚱하게 낮은 점수가 나오기도 했다.

처음엔 내 코드 버그인 줄 알고 뒤졌는데, 아니었다. 작은 다국어 모델이 원래 가진 한계였다. 완벽한 의미 지도가 아니라, 군데군데 길이 어긋난 지도인 셈이다. 재밌는 건, 이 '어긋남'이 게임에서는 오히려 난이도이자 재미가 된다는 거다. 사람의 직관과 모델의 직관이 어긋나는 지점을 찾아가는 놀이가 되니까.

## 마무리 — AI가 한 일, 내가 판단한 일

오늘도 코드를 빠르게 짜준 건 AI(클로)였다. 하지만 '무엇이 이상한지' 알아챈 건 내 몫이었다.

| AI가 한 일 | 내가 판단한 일 |
|---|---|
| 모델 로딩·인코딩·코사인 계산 코드 작성 | CPU 전용으로 못 박기 — 내 환경 기준의 결정 |
| 점수가 몰리는 현상을 재보정 코드로 해결 | "점수가 다 비슷해서 재미없다"를 문제로 인식한 것 |
| 힌트·웜콜드 로직 구현 | 게임이 너무 어렵다고 느끼고 난이도를 낮추자고 방향 잡은 것 |
| '포도가 왜 3위냐'에 모델 한계라고 설명 | 그걸 버그로 덮지 않고 게임의 재미로 남겨두기로 한 판단 |

도구가 코드를 대신 짜줄수록, 남는 몫은 **"이게 왜 이상하지"를 알아채고 어디까지 다듬을지 정하는 쪽**이었다.

## 다음 예고

오늘 만진 건 단어를 하나씩 따로 벡터로 본 것, 즉 정적인 지도였다. 하지만 실제 문장은 '나는 너를'과 '너는 나를'처럼 **순서가 뜻을 바꾼다.** 강의가 짚은 '순서의 벽'이 여기다. 다음은 단어 하나가 아니라, 앞 단어를 기억하며 흐름을 읽는 구조 쪽으로 들어가 볼 생각이다.
