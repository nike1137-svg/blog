[포트를 열지 않고 맥미니를 빌렸다](/blog/posts/borrowed-without-opening-a-port/)를 닫으면서 **"다음은 VS Code와 오르카를 연습하는 일"**이라고 적어뒀다. 그 줄기는 따로 굴러가고 있고, 오늘 쓰는 건 수업 쪽이다.

두 달 가까이 MCP라는 말을 계속 들었다. 용어 정리로 두 번 적었고, 앱에 남이 만든 서버를 붙여도 봤다. 그런데 **서버를 내 손으로 만들어 본 적은 없었다.** 오늘 그걸 했다.

## 1. 붙어 있는 것과 만들어 보는 것

MCP는 도구를 제공하는 프로그램과 AI 앱 사이에 공통 규칙을 두는 약속이다. 규칙이 있으니 같은 서버를 Claude Code에도 붙이고 다른 앱에도 붙일 수 있다. 여기까지는 알고 있었다.

내가 몰랐던 건 그 앞이었다.

**컴퓨터에 파일이 있고 함수가 있어도 모델은 그걸 자동으로 알아채지 않는다.** 따로 알려줘야 한다. 이름이 무엇이고, 어떤 설명이며, 입력은 어떤 모양이어야 하는지.

네트워크를 하던 시절로 옮기면 이해가 쉽다. **장비가 랙에 꽂혀 있는 것과 그 장비가 NMS에 등록된 것은 다른 얘기다.** 꽂혀만 있으면 관제 화면에 안 뜬다. MCP 등록이 정확히 그 자리다.

## 2. 가상 팀을 내 학습 기록으로 바꿨다

수업 예제는 가상 제품팀의 주간 업무 기록을 읽는 서버였다. 그대로 따라 만들면 손은 익는데 남는 게 없다. 그래서 데이터를 내 것으로 바꿨다.

그런데 **파일 이름만 바꾸면 안 된다는 걸 바꾸는 도중에 알았다.**

예제의 완료 기준은 이랬다. 코드를 다 쓴 것과 사용자가 쓰는 환경에 반영된 것은 다른 사건이라는 것. 그래서 개발이 끝났어도 배포 전이면 완료가 아니다.

내 학습 기록에 같은 구조가 있었다.

| 예제의 기준 | 내 기준 |
|---|---|
| 개발 완료 ≠ 배포 완료 | **이해 완료 ≠ 블로그 발행** |
| 사용자 환경에 반영됐나 | **글로 옮겼나** |

머리로 정리한 것과 글로 써서 남긴 것은 다른 사건이다. 이 블로그를 쓰면서 매일 확인하는 일이기도 하다. 그래서 `이해 완료` 와 `블로그 발행` 을 상태로 나누고, 이해한 날짜와 발행한 날짜를 각각 칸으로 뒀다.

`프로세스와 이식성` 항목을 일부러 두 주차에 걸쳐 넣었다. 첫 주에는 이해만 끝나고 발행이 비어 있고, 둘째 주에는 발행 날짜가 들어온다. **같은 항목이 판정만 바뀌는 자료**를 만들어 둔 것이다.

이름만 갈아끼우는 게 아니라 **자료가 달라지면 그 자료에서 읽어야 할 의미와 기준까지 바뀐다.** 이게 오늘 만든 것 중 손이 아니라 머리를 쓴 부분이었다.

## 3. 두 겹으로 검사하게 만들었다

도구가 받는 입력은 `week` 하나다. 문자열이고, 쓸 수 있는 값은 두 개다.

여기서 검사가 두 겹이라는 걸 처음 구분했다.

- **입력 스키마** — 자료형이 맞는가. 문자열인가
- **함수 안의 목록 검사** — 우리가 쓸 수 있는 값인가

`"w38"` 도 문자열이다. 스키마는 통과한다. **하지만 그 주차 자료는 없다.**

서식이 제대로 채워졌는지 보는 창구와, 신청 자격이 되는지 보는 창구는 다르다. 하나로 합치면 서식만 맞으면 다 통과한다.

그래서 함수 안에 쓸 수 있는 주차 목록을 두고, 거기 없으면 이유를 적어 거절하게 했다.

```python
if selected_week not in WEEK_FILES:
    raise ValueError(
        f"week는 {' 또는 '.join(WEEK_FILES)} 를 사용하세요. 받은 값: {week!r}"
    )
```

데이터를 찾는 방식도 한 줄 신경 썼다.

```python
DATA_DIR = Path(__file__).with_name("data")
```

현재 작업 폴더가 아니라 **이 소스 파일 옆의 폴더**를 찾는다. 앱이 서버를 어디서 실행하든 데이터 위치가 흔들리지 않는다. 등록 설정에는 소스 파일까지만 적고, 데이터는 소스가 자기 옆에서 찾는 구조다.

## 4. 홈 루트에 등록해버렸다

붙이는 건 명령 한 줄이었다. 그리고 첫 줄에서 걸렸다.

```
File modified: C:\Users\nike1\.claude.json [project: C:\Users\nike1]
```

**홈 루트 프로젝트에 등록됐다.** 명령을 홈 폴더에서 실행했기 때문이다. 목록에서는 잘 보이는데 정작 작업하던 폴더에서는 안 잡혔다.

작업 폴더를 홈 루트에 만들지 않는다는 규칙을 지난달에 세워뒀다. 폴더는 안 만들었는데 **설정을 거기에 만들고 있었다.** 같은 실수가 자리만 바꿔서 나온 것이다.

사용자 범위로 다시 등록해서 해결했다. 어느 폴더에서 켜도 잡히도록.

그리고 `uv` 실행 파일을 절대경로로 박아 넣었다. 터미널에서는 이름만 쳐도 되는데 앱에서는 못 찾을 수 있다. **터미널과 앱이 서로 다른 실행 파일 목록을 보기 때문이다.** 이건 미리 알고 넣은 게 아니라, 환경 확인할 때 경로가 유난히 긴 걸 보고 넣어둔 것이다.

## 5. 4건이 원본과 맞았다

붙은 뒤 첫 주차를 읽혔다. 확인한 건 답변이 아니라 그 앞이었다.

- 호출한 도구 이름이 내가 만든 그것인가
- 보낸 입력이 내가 요청한 주차인가
- 돌아온 게 4건이고, 원본에서 비어 있던 칸이 여전히 비어 있는가

세 개가 다 맞았다. 메모 문장까지 원본과 같았다.

**답변만 보면 이걸 못 본다.** 파일을 그냥 열어 읽고 답해도 내용은 맞을 수 있다. 그러면 내용은 맞지만 내가 만든 통로를 확인한 게 아니다. 그래서 호출 기록을 봐야 한다.

## 6. 서버는 이유를 말했는데 대화에는 오지 않았다

다음으로 없는 주차를 물었다.

거절됐다. 여기까지는 예상대로다. 그리고 이 거절은 **서버가 안 뜬 것과 완전히 다르다.** 요청이 도구까지 도달해서, 함수가 입력을 검사한 뒤 거절한 것이다. 검사가 살아 있다는 증거다.

문제는 그 다음이었다. 대화에 돌아온 건 이것뿐이었다.

```
Error executing tool get_study_log
```

**내가 적어 넣은 이유가 어디에도 없었다.** 코드에는 분명히 "w36 또는 w37을 사용하세요"라고 문장을 넣어뒀는데.

반송된 우편이 돌아왔는데 **사유 도장이 안 찍혀 있는 셈이다.** 주소가 틀렸는지, 수취인이 없는지, 우편함이 꽉 찼는지 알 수가 없다. 봉투는 돌아왔으니 뭔가 잘못된 건 확실한데.

[내 쪽에서 통과한 것이 상대 쪽에서도 통과하지는 않았다](/blog/posts/passed-on-my-side-not-theirs/)에 이런 걸 적어뒀다. 그때는 내 쪽 검증이 여덟 개 다 통과하는데 브라우저에서만 막혔다. **확인하는 자리와 쓰는 자리가 다르다**는 이야기였다.

오늘은 같은 모양이 한 겹 안쪽에서 나왔다. **서버 쪽에서는 이유를 말했는데, 그 말이 대화까지 오지 않았다.** 내 쪽에서 던진 것이 저쪽에 도착하지는 않았다.

원인은 예외를 감싸지 않은 것이었다. 파이썬의 일반 예외를 그대로 올리면 SDK가 안전하게 뭉개서 "도구 실행 오류"로만 넘긴다. 도구 전용 오류로 다시 싸야 메시지가 실린다.

```python
except ValueError as error:
    # 맨 예외는 호스트에 일반 오류로만 보인다.
    # 도구 오류로 감싸야 이 메시지가 대화까지 전달된다.
    raise ToolError(str(error)) from None
```

세 줄이다. 교재에도 이 자리에 같은 처리가 있었다. **읽을 때는 왜 있는지 몰랐고, 없이 만들어보고 나서 알았다.**

고치고 나서 또 한 번 걸렸다. 같은 자리에서 다시 물었는데 여전히 옛 메시지가 나왔다. **소스를 고쳐도 이미 떠 있는 서버 프로세스는 옛 코드를 물고 있다.** 새 대화를 열어야 새 코드로 서버가 시작된다.

## 7. 고친 뒤 AI의 진단이 달라졌다

여기가 오늘의 진짜 소득이다.

메시지가 안 실려 오던 상태에서 같은 오류를 다른 세션에 던져봤다. 이렇게 답했다.

> 서버 코드가 예외 처리 없이 그대로 터뜨리는 구조로 보입니다.

**틀렸다.** 검사는 있었다. 메시지도 있었다. 안 넘어온 것뿐이었다. 다만 그 세션이 **"추측이므로 소스를 직접 확인해야 확정됩니다"**라고 덧붙인 건 맞는 태도였다. 근거 없이 단정하지는 않았다.

고친 뒤 같은 걸 물었다. 이번에는 파일 이름과 **줄 번호까지** 짚었다. 허용 목록이 몇 번째 줄에 있고, 그래서 파일만 만들어도 안 되고 목록에도 등록해야 통과한다는 설명까지 붙었다.

같은 질문, 같은 코드, 같은 모델이다. **달라진 건 오류가 이유를 싣고 왔는지뿐이다.**

오류 메시지를 잘 쓰라는 말을 여러 번 들었다. 사용자 친절 같은 얘기로 흘려들었다. 오늘 확인한 건 그게 아니다.

**이유를 실어 보내면 다음에 그걸 읽는 쪽의 진단이 정확해진다.** 그게 사람이든 AI든.

## 8. 편해지는 제안을 보류했다

그 세션이 개선안을 하나 냈다. 목록을 손으로 관리하지 말고 폴더 안의 파일을 자동으로 찾게 하자는 것.

편해진다. 주차를 추가할 때 코드를 안 고쳐도 된다.

**안 하기로 했다.** 검사 한 겹이 사라진다.

지금은 "쓸 수 있는 값인가"를 본다. 자동 인식으로 바꾸면 "파일이 있는가"로 약해진다. 비슷해 보이지만 다르다. 앞쪽은 내가 정한 목록이고, 뒤쪽은 폴더에 뭐가 들어왔는지에 따라 달라진다.

실습 서버라 파일 두 개짜리다. 그래도 **두 겹인 것이 지금 상태에서는 맞다**고 적어둔다. 나중에 자료가 늘어 손이 많이 가면 그때 다시 볼 일이다.

## 9. 오늘 내가 판단한 일

AI가 한 일과 내가 정한 일을 나눠 적는다.

**AI가 한 일**

- 서버 코드와 데이터 파일 작성
- 패키지 설치, 실행 명령 검증
- 오류를 도구 오류로 감싸는 수정

**내가 판단한 일**

- **가상 팀 대신 내 학습 기록을 넣기로 한 것.** 예제를 그대로 돌리면 손만 익는다. 완료 기준까지 내 것으로 바꿔야 이름만 갈아끼운 게 아니게 된다.
- **`이해 완료` 와 `블로그 발행` 을 나눈 것.** 예제의 개발/배포 구분을 내 자리에 옮긴 것이다. 이 구분이 없으면 정리만 해놓고 완료로 세게 된다.
- **답변이 아니라 호출 기록을 본 것.** 내용이 맞는 것과 내가 만든 통로로 온 것은 다르다. 파일을 그냥 읽어도 내용은 맞는다.
- **없는 주차를 일부러 물어본 것.** 정상만 확인하면 검사가 도는지 모른다. 거절이 돌아오는 걸 봐야 안다.
- **AI의 첫 진단을 그대로 믿지 않은 것.** "예외 처리가 없어 보인다"는 말에 코드를 뒤엎지 않고 소스를 열어봤다. 검사는 있었다.
- **자동 인식 제안을 보류한 것.** 편해지는 쪽이 아니라 검사가 남는 쪽을 골랐다.

**틀린 자리도 남긴다.** 홈 루트에 등록한 건 몰라서 그런 게 아니다. 폴더를 홈 루트에 만들지 않는다는 규칙을 이미 세워뒀는데, 그게 설정 파일에도 적용된다는 걸 연결하지 못했다. 명령을 어느 폴더에서 실행하는지가 결과를 바꾼다는 것도 그 자리에서 알았다.

## 10. 남은 질문

**오류를 어디까지 실어 보내야 하는지는 아직 모르겠다.**

오늘은 "허용된 값이 아니다"를 그대로 실어 보냈다. 이건 알려줘도 문제없는 정보다. 그런데 실서비스 자료를 읽는 서버라면 어떨까. 파일 경로가 그대로 나가거나, 데이터베이스 오류 문장이 통째로 대화에 실리면 그건 새는 것에 가깝다.

교재에도 이 자리에 짚어둔 게 있었다. 서버가 응답에 넣은 것은 그대로 호스트로 간다는 것. **감춰지는 게 아니라, 감추기로 정한 것만 감춰진다.**

그러니까 **"진단에 필요한 만큼"과 "내보내면 안 되는 것" 사이의 선**이 남는다. 오늘 만든 건 실습 파일 두 개짜리라 그 선을 그을 일이 없었다. 실제 자료를 붙이면 첫 번째로 만날 문제일 것 같다.

다음은 아직 정하지 않았다. 두 주차를 비교해 판정 기준을 따로 남기는 일이 자연스러운 순서인데, 오늘은 서버가 붙고 오류가 도착하는 것까지만 봤다.
