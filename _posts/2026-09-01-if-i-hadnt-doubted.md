> ⚠️ 터널 주소·토큰·API 키는 이 글에 담지 않는다. 과정과 배운 것만 남긴다.

어제 글은 [규칙은 적어 뒀는데 발동할 자리가 없었다](/blog/posts/rules-without-a-trigger/)로 끝났다. 메인퀘스트를 마치고 3일을 되짚은 글이었다.

오늘은 그런 글이 아니다. **수업에서 본 것을 혼자 다시 세워 본 복습**이다. 새로 만든 것도 없고 대단한 결론도 없다.

일의 경계를 먼저 적어 둔다. **코랩에 모델 서버를 올리는 데까지는 수업 노트북을 그대로 따라 내가 진행했다.** 거기까진 한 번에 됐다. AI와 상의를 시작한 건 그다음, **그 서버를 바깥으로 여는 구간**부터다. 그리고 막힌 것도 전부 그 구간이었다.

---

## 1. 오늘 세우려던 것

n8n으로 AI 워크플로를 만들면 보통 OpenAI 노드를 쓴다. 그런데 그건 호출할 때마다 돈이 든다. 연습하면서 돈을 쓰고 싶지 않았다.

그래서 이런 구조를 만드는 게 오늘 과제였다.

```
n8n (교육기관 서버)
  └ AI Agent
      └ OpenAI Chat Model ──→ 터널 주소
                                  ↓
                            코랩 안의 모델 서버
                                  └ Qwen 4B
```

**핵심은 "OpenAI 노드를 그대로 두고 주소만 바꾼다"** 는 것이다. 모델 서버가 OpenAI와 같은 형식으로 대답하도록 만들어져 있어서, n8n 입장에선 OpenAI에 접속하는 줄 알고 동작한다. 노드를 갈아끼울 필요가 없다.

> **알고 가기** — 이건 전화기를 바꾸는 게 아니라 **단축번호에 저장된 번호만 바꾸는 것**에 가깝다. 전화기(노드)는 그대로고, 거는 곳만 달라진다. 상대가 같은 말투로 받아주기만 하면 전화기는 눈치채지 못한다.

그리고 코랩은 남의 컴퓨터라 바깥에서 부를 주소가 없다. 그래서 **터널**이 필요하다. 이 발상은 5주 전과 똑같았다 — 그때도 코랩에 모델을 올리고 터널로 열었다.

이 구조 자체는 내가 수업에서 이해한 그대로였고, 끝까지 그대로 맞았다. 틀린 건 구조가 아니라 **바깥으로 여는 구간에서 받은 지시**였다.

## 2. "눌러도 안전하다"는 말이 서버를 껐다

수업 노트북을 내 드라이브로 복사해 위에서부터 돌렸고, **서버 실행 셀로 모델 서버가 정상적으로 떴다.** 로그 끝에 준비 완료가 찍혔다. 여기까지가 내가 혼자 한 부분이고, 문제없이 됐다.

문제는 그다음, 이걸 바깥으로 여는 구간부터였다.

모델 서버를 띄우는 셀은 계속 돌아가는 게 정상이다. 서버니까 켜져 있어야 한다.

터널을 붙이려고 새 셀을 만들었는데, 그 셀들이 전부 도는 것처럼 보였다. 코랩은 **한 번에 한 셀만** 실행하고, 위가 안 끝나면 아래는 줄만 서 있다. 도는 아이콘이 세 개라고 세 개가 일하는 게 아니었다.

줄이 막혀서 **런타임 중단**을 눌렀다. 이걸 눌러도 되냐고 물었을 때 받은 답은 이랬다.

> 서버는 별개 프로세스라 이거 정지해도 서버는 영향 없습니다. 안심하고 정지하세요.

**틀린 말이었다.** 그대로 했더니 서버가 죽었다. 로그 끝에 이렇게 남아 있었다.

```
(EngineCore) KeyboardInterrupt
```

에러로 죽은 게 아니라 **정지 신호를 맞고 죽은 것**이다. 수업 노트북 셀로 잘 떠 있던 서버가, 터널을 붙이려다 이렇게 됐다.

죽은 서버를 다시 띄우려고 받은 코드는 이렇게 생겼다.

```python
subprocess.Popen([...])          # 노트북과 같은 그룹
```

부모(노트북)에게 간 정지 신호가 자식(서버)에게도 갔다. 이걸 막는 방법은 한 줄이다.

```python
subprocess.Popen([...], start_new_session=True)   # 서버를 다른 방으로
```

**처음부터 이 한 줄이 들어 있었어야 했다.** 없는 채로 받았고, "눌러도 안전하다"는 말까지 같이 받았다. 두 개가 겹쳐서 서버가 죽었다.

> **알고 가기** — 자식 프로세스가 부모와 같은 그룹에 있으면, 부모에게 간 정지 신호가 자식에게도 간다. 한 방에 같이 있으면 불을 끌 때 같이 어두워지는 것과 같다. 방을 따로 쓰게 하면 그 일이 안 생긴다.

한 줄을 넣은 뒤로는 중단을 눌러도 서버가 살아 있었다. **참는 것보다 안 죽게 만드는 쪽이 확실했다.**

## 3. 12분이 정상이었다

다시 띄운 서버가 이번엔 안 뜨는 것 같았다. 확인 셀이 `대기중...`만 반복했다.

느리다고 말했더니 "기다리라"는 답이 돌아왔다. 21번까지 세도 그대로였다. 그래서 다시 말했다 — **실패만 하지 말고 좀 더 집중해서 생각해 보라고.**

그 뒤에 나온 답이 처음으로 근거가 있었다. 첫 성공 때 로그의 시각을 세어 보니 서버가 준비되기까지 **12분 15초**가 걸렸다는 것이다. 모델을 GPU에 올리고 연산 커널을 하나씩 컴파일하는 시간이었다. 로그에 그 흔적이 계속 찍히고 있었는데, 같은 줄이 반복되니 멈춘 것처럼 보였을 뿐이다.

**멈춘 것과 오래 걸리는 것은 화면이 똑같다.** 구별하려면 로그를 봐야 한다.

같은 자리에서 하나 더 나왔다. 강사님 원본에 있던 옵션 세 개가 내가 받은 코드에서 빠져 있었다는 것이다. 답변에서 생각 과정을 분리해 주는 옵션과, 도구 호출을 처리하는 옵션들이었다. 그대로 갔으면 n8n에 붙인 다음에야 이상하다는 걸 알았을 것이고, 12분을 또 썼을 것이다.

**이것도 내가 한 번 더 묻지 않았으면 안 나왔다.**

## 4. 토큰이 아니라 잔재였다

터널을 여는데 인증이 거부됐다.

```
authentication failed: The authtoken you specified is properly formed, but it is invalid.
```

토큰 형식은 맞는데 무효라는 것이다. 대시보드에서 다시 확인했다. 같은 값이었다. **토큰은 문제가 아니었다.**

앞선 시도에서 인증에 실패한 프로세스가 죽지 않고 남아 그다음 연결을 막고 있었다. 붙이기 전에 먼저 죽이는 한 줄을 넣으니 바로 통과했다.

```python
ngrok.kill()          # 남아 있던 것부터 정리
```

에러 메시지는 "토큰이 무효하다"고 말했지만, 원인은 **치우지 않은 잔재**였다. 메시지가 가리키는 곳과 원인이 있는 곳이 달랐다.

그리고 이 직전에, 멈춘 줄 알았던 셀이 사실은 이미 끝나서 주소를 뱉어 놓은 적도 있었다. 화면을 잘못 읽고 "멈췄다"는 판정을 받았지만, 실제로는 성공해 있었다.

## 5. 확인은 안쪽부터 바깥쪽으로

중간에 터널 주소로 접속했더니 502가 떴다. 이 숫자가 알려주는 건 **"터널은 살아 있는데 그 뒤가 없다"** 였다. 문제는 바깥이 아니라 안쪽이다.

그래서 순서를 정했다.

1. 코랩 안에서 자기 자신에게 물어보기 — 서버가 살았는가
2. 터널 주소로 밖에서 물어보기 — 길이 뚫렸는가
3. n8n에서 실제로 실행 — 붙었는가

이 순서를 지키니 매번 어디가 문제인지 한 번에 갈렸다. 안쪽이 안 되면 바깥을 봐야 소용없고, 안쪽이 되는데 바깥이 안 되면 그 사이만 보면 된다.

마지막에 답변이 나왔을 때 확인한 건 두 가지였다. 한국어로 대답한다는 것, 그리고 **생각 과정과 답변이 분리돼서 온다는 것.** 앞에서 되살린 옵션이 여기서 값을 했다.

n8n 쪽 마지막 조각은 직접 넣었다. AI Agent에 질문이 지정돼 있지 않아 빨간 표시가 남아 있었는데, 앞 노드가 가져온 위키피디아 본문을 프롬프트로 연결했다. 모델 연결과는 무관한, 원래부터 비어 있던 칸이었다.

## 6. 이건 학습의 복습이다

분명히 해 두자면, **오늘 새로 만든 것은 없다.** 수업에서 본 구조를 혼자 다시 세워 본 것이고, 목적은 작동하는 서비스가 아니라 **개념을 손으로 확인하는 것**이었다.

그래서 얻은 것도 결과물이 아니라 이해 쪽이다.

- 같은 형식으로 대답하기만 하면 **부르는 쪽은 상대가 누구인지 모른다** — 노드를 안 바꾸고 주소만 바꿔도 되는 이유
- 코랩은 빌린 방이라 **주소가 없다** — 터널이 필요한 이유
- 포트를 어디에 여느냐로 안팎이 갈린다 — 7월에 정리해 둔 것이 오늘 그대로 쓰였다

그리고 이 구성은 **연습용이지 서비스용이 아니다.** 코랩은 시간이 지나면 꺼지고, 꺼지면 터널 주소도 사라진다. 다시 켜면 주소가 바뀌니 n8n 설정도 다시 고쳐야 한다. 실서비스에 붙일 물건이 아니라는 걸 알고 쓰는 것과 모르고 쓰는 것은 다르다.

## 오늘 내가 판단한 것

| AI가 한 일 | 내가 판단한 것 |
|---|---|
| (코랩·vLLM 구간은 관여 없음) | **수업 노트북으로 모델 서버를 직접 올린 것** — 여기까진 한 번에 됐다 |
| 재시작용 셀 코드 작성 — 서버를 분리하는 줄이 빠져 있었다 | 화면이 안 바뀔 때 **기다리는 게 맞는지 되물은 것** |
| "정지해도 서버는 영향 없다"고 안내 (틀린 안내) | 서버가 죽은 뒤 **그 안내가 원인일 수 있다고 본 것** |
| 실행 중인 셀 위에 새 셀을 실행하라고 지시 | **"지금 동작 중인데 로그가 나오냐"고 지적한 것** — 지시의 모순을 내가 잡았다 |
| "기다리라"는 답을 반복 | **"실패만 하지 말고 집중해서 생각해 보라"고 요구한 것** — 이 뒤에야 원인 분석이 나왔다 |
| 화면에 없는 내용을 말함 | **그 자리에서 끊은 것** |
| 과정을 복잡하게 벌림 | **"강사님 사본 그대로 돌리면 되는 거 아니냐"고 되돌린 것** |
| n8n 자격증명 생성·노드 연결 | AI Agent 프롬프트는 **수업에서 배운 대로 직접 설정한 것** |

오늘 가장 중요했던 건 **의심을 멈추지 않은 쪽**이었다. 코드도 지시도 자신 있게 왔지만, 그중 몇 개는 틀렸다. 그걸 걸러낸 건 도구가 아니라 "이게 맞나" 하고 한 번 더 물은 쪽이었다.

도구에 권한은 준다. 하지만 **틀렸을 때 알아채는 몫은 넘어가지 않는다.** 오늘은 그게 네 번 있었다.

**다음은** 오늘 빌려 쓴 남의 방 대신, 내가 가진 **젬마4 12B**를 직접 붙여 볼 차례다. 오늘 것이 개념을 확인하는 연습이었다면, 그다음은 내 기기에서 내 모델로 같은 구조가 서는지 보는 일이다.
