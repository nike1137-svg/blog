## 갈래 1. 모델을 다루는 기본 동작

### 1. 바인딩(Binding)
- **정의**: 프로그램 안에서 객체·함수·데이터를 서로 **연결해 하나로 묶어 쓰는 것**.
- **비유**: 콘센트에 플러그를 꽂는 것 — 꽂아야(연결돼야) 전류(값)가 흐른다.
- **예시**: Pydantic AI에서 Agent에 도구 함수를 연결해 두면, 호출할 때마다 그 함수를 그대로 쓸 수 있다.

### 2. 제로샷 학습(Zero-shot Learning)
- **정의**: 모델이 **해당 작업의 예시를 하나도 보지 않고**, 설명(지시)만으로 새 작업을 수행하는 것.
- **비유**: 요리책도 안 보고 재료 이름만 듣고 처음 보는 요리를 만들어내는 것.
- **예시**: 번역 예시를 하나도 안 보여줬는데 "이 문장을 프랑스어로 바꿔줘"에 바로 답하면 제로샷이다.

### 3. 프로토타이핑(Prototyping)
- **정의**: 완성품을 만들기 전에 아이디어나 기능을 **빠르게 구현해 실제로 동작하는지** 확인하는 과정.
- **비유**: 집을 짓기 전에 종이 모형부터 만들어 구조가 말이 되는지 보는 것.
- **예시**: LoRA 파인튜닝을 본격적으로 돌리기 전에 데이터 몇 줄로 스크립트가 끝까지 도는지 먼저 확인하는 것도 프로토타이핑이다.

### 4. 스키마(Schema)
- **정의**: 데이터가 어떤 **구조와 형식**을 가져야 하는지 정의한 규칙(설계도).
- **비유**: 서류 양식의 빈칸 — 이름 칸, 날짜 칸이 정해져 있어야 아무 종이나 서류로 인정되지 않는다.
- **예시**: Pydantic AI에서 Agent의 출력 형식을 스키마로 정해두면, 모델이 딴 형태로 답해도 정해진 틀에 맞춰 걸러진다.

### 5. API(Application Programming Interface)
- **정의**: 프로그램이 다른 프로그램·서비스의 기능을 **요청하고 결과를 받을 수 있게** 해주는 통신 창구.
- **비유**: 식당 주방과 손님 사이의 종업원 — 손님(내 코드)이 주문(요청)하면 주방(서버)에 전달하고 음식(결과)을 받아다 준다.
- **예시**: 날씨 API를 호출하면 내 코드가 직접 날씨를 계산하지 않아도 값을 받아올 수 있다.

### 6. API Key
- **정의**: API를 쓸 권한을 인증하기 위한 **비밀 문자열**.
- **비유**: 건물 출입증 — 있어야 문이 열리고, 남에게 보여주면 남도 내 대신 드나들 수 있다.
- **예시**: 코드에 그대로 적으면 GitHub에 올릴 때 같이 노출된다. `.env`로 빼두는 이유다.

## 갈래 2. 모델을 학습시키는 방법

### 7. CPT(Continued Pre-Training)
- **정의**: 이미 학습이 끝난 LLM에 **새로운 대규모 데이터를 추가로** 학습시키는 방식. 특정 분야 지식이나 새 어휘를 모델에 심을 때 쓴다.
- **비유**: 다 배운 사람에게 새 전공 서적을 통째로 다시 읽히는 것 — 기존 지식 위에 새 지식층을 덧쌓는다.
- **예시**: 표준어만 알던 모델에 사투리 텍스트를 대량으로 더 학습시키면 CPT에 해당한다.

### 8. 파인튜닝 / 미세조정(Fine-tuning)
- **정의**: 이미 학습된 모델을 **특정 작업·목적에 맞는 데이터**로 추가 학습시키는 것.
- **비유**: 다재다능한 신입사원에게 우리 회사 업무 매뉴얼만 따로 교육시키는 것.
- **예시**: 지금 진행 중인 Gemma 12B → 사투리-표준어 변환 작업이 파인튜닝이다. CPT가 지식을 넓히는 쪽이라면 파인튜닝은 특정 작업에 맞춰 좁히는 쪽에 가깝다.

### 9. Unsloth(언슬로스)
- **정의**: LLM 파인튜닝을 **더 빠르고 적은 메모리**로 할 수 있게 지원하는 도구.
- **비유**: 같은 짐을 나르는데 일반 손수레 대신 경량 카트를 쓰는 것.
- **예시**: 맥미니 24GB처럼 메모리가 넉넉하지 않은 환경에서 LoRA 파인튜닝을 돌릴 때 도움이 된다.

### 10. 가중치 공개 모델(Open-weight Model)
- **정의**: 학습된 모델의 **가중치(파라미터 값)를 공개**해서 누구나 다운로드하고 실행하거나 추가 학습할 수 있는 모델.
- **비유**: 완성된 레시피를 통째로 공개해서 누구나 그대로 요리하거나 재료만 바꿔볼 수 있게 하는 것.
- **예시**: Gemma·LLaMA·Qwen이 가중치 공개 모델이라 로컬(맥미니)에서 내려받아 파인튜닝할 수 있다.

### 11. 코퍼스(Corpus)
- **정의**: 언어 모델 학습이나 언어 연구에 쓰는 **대규모 텍스트 데이터 모음**.
- **비유**: 도서관 서고 전체 — 그 안의 문장들을 모아 모델에게 읽힌다.
- **예시**: 사투리-표준어 변환 파인튜닝에는 사투리 문장과 표준어 문장이 짝지어진 코퍼스가 필요하다.

### 12. 토크나이저(Tokenizer)
- **정의**: 텍스트를 LLM이 처리할 수 있는 **토큰 단위로 쪼개고 숫자로 변환**하는 도구.
- **비유**: 문장을 레고 블록 단위로 잘라 각 블록에 번호표를 붙이는 것.
- **예시**: 같은 문장이라도 모델마다 토크나이저가 달라서 토큰 개수(=비용)가 달라질 수 있다.

## 갈래 3. 성능을 재는 숫자

### 13. BLEU
- **정의**: 번역·문장 변환 결과가 정답 문장과 **얼마나 비슷한지** 평가하는 지표. 점수가 높을수록 좋다.
- **비유**: 모범 답안과 내 답을 겹쳐놓고 겹치는 단어·구절이 얼마나 되는지 세는 채점.
- **예시**: 사투리→표준어 변환 결과가 정답 표준어 문장과 얼마나 겹치는지 BLEU로 잴 수 있다.

### 14. F1 점수
- **정의**: 정밀도(Precision)와 재현율(Recall)의 **조화평균**으로 분류 모델 성능을 평가하는 지표.
- **비유**: 정확하게 맞히는 것(정밀도)과 빠뜨리지 않는 것(재현율)을 함께 반영한 종합 성적표.
- **예시**: 스팸 분류기가 스팸을 정확히 잡으면서도 진짜 스팸을 놓치지 않는지 함께 볼 때 F1을 쓴다.

### 15. 스칼라(Scalar)
- **정의**: 하나의 숫자값으로 표현되는 데이터. 예: 3, 0.5, -10.
- **비유**: 벡터가 "화살표"라면 스칼라는 그냥 "숫자 하나" — 방향 없이 크기만 있다.
- **예시**: BLEU 점수나 F1 점수처럼 결과가 숫자 하나로 나오면 스칼라값이다.

### 16. 산술평균
- **정의**: 모든 값을 더한 뒤 **값의 개수로 나눈** 평균.
- **비유**: 여러 사람이 낸 돈을 다 합쳐 인원수로 나눠 1인당 부담액을 구하는 것.
- **예시**: 여러 문장의 BLEU 점수를 산술평균 내면 전체 데이터셋의 평균 성능이 된다.

### 17. 조화평균
- **정의**: 여러 값의 **역수를 평균낸 뒤 다시 역수**를 취하는 평균. F1 점수 계산에도 쓰인다.
- **비유**: 갈 때 시속 60, 올 때 시속 40으로 왕복했을 때 전체 평균 속도 — 산술평균과 달리 낮은 값 쪽에 더 끌려간다.
- **예시**: 정밀도와 재현율 중 하나가 너무 낮으면 조화평균(F1)도 낮게 나와, 둘 다 잘해야 점수가 높아진다.

### 18. 양의 계수
- **정의**: 0보다 큰 계수. 변수와 결과 사이에 **양(+)의 방향으로** 영향을 준다.
- **비유**: 온도가 오를수록 아이스크림 판매량도 같이 오르는 관계 — 계수가 양수면 같은 방향으로 움직인다.
- **예시**: 회귀식에서 어떤 변수의 계수가 양수면, 그 변수가 커질수록 예측값도 커진다는 뜻이다.

### 19. 파라미터(Parameter)
- **정의**: LLM이 학습 과정에서 조정한 **수치적 값**. 입력을 처리하고 다음 토큰을 예측하는 데 쓰인다.
- **비유**: 악기의 수많은 조율 나사 — 하나하나 조금씩 맞춰지면서 전체 소리(모델 성능)가 완성된다.
- **예시**: Gemma 12B는 이 조율 나사가 약 120억 개 있다는 뜻이다.

### 20. 12B
- **정의**: Billion(10억)을 뜻하는 **모델 규모 표기**. 12B = 약 120억 개의 파라미터. 비트·바이트를 뜻하지 않는다.
- **비유**: 책의 "몇 쇄"가 아니라 "총 글자 수"를 나타내는 표기 — 클수록 담을 수 있는 정보(조율 나사 개수)가 많다.
- **예시**: 지금 쓰는 Gemma 4 12B는 파라미터가 약 120억 개인 모델이라는 뜻이다.

## 갈래 4. LLM 모델 계열과 구조

### 21. LLaMA
- **정의**: Meta가 개발한 **LLM 모델 계열**.
- **비유**: 자동차의 한 브랜드처럼, LLM이라는 큰 범주 안의 한 제조사 라인업.
- **예시**: Gemma·Qwen과 계열은 다르지만 모두 가중치 공개 모델이라는 공통점이 있다.

### 22. Gemma
- **정의**: Google이 개발한 **LLM 모델 계열**.
- **비유**: LLaMA가 한 브랜드라면 Gemma는 또 다른 브랜드 — 같은 LLM 범주지만 다른 제조사 라인업.
- **예시**: 지금 로컬에서 파인튜닝 중인 모델이 이 계열의 Gemma 4 12B다.

### 23. Qwen
- **정의**: Alibaba가 개발한 **LLM 모델 계열**.
- **비유**: LLaMA·Gemma와 나란히 있는 또 하나의 제조사 라인업.
- **예시**: 같은 파인튜닝 방법(LoRA)을 Qwen 계열 모델에도 그대로 적용해볼 수 있다.

### 24. MoE(Mixture of Experts)
- **정의**: 여러 Expert(전문가 서브네트워크) 중 입력에 따라 **필요한 일부만 골라 계산**하는 LLM 구조. Router가 어떤 Expert를 쓸지 정한다.
- **비유**: 병원에서 접수처(Router)가 증상을 보고 필요한 전문의(Expert)에게만 보내는 것 — 전체 의사가 다 진료할 필요는 없다.
- **예시**: 파라미터 전체를 항상 다 쓰지 않기 때문에, 같은 파라미터 수 대비 계산량을 아낄 수 있다.

### 25. 임베딩(Embedding)
- **정의**: 텍스트나 데이터를 **의미를 비교·계산할 수 있는 숫자 벡터**로 변환하는 것.
- **비유**: 단어를 지도 위 좌표로 찍는 것 — 뜻이 비슷한 단어일수록 지도에서 가까운 자리에 놓인다.
- **예시**: RAG에서 문서를 검색할 때, 질문과 문서를 각각 임베딩으로 바꿔 좌표가 가까운 문서를 찾는다.

### 26. 다중모달(Multimodal)
- **정의**: 텍스트·이미지·음성·영상 등 **여러 종류의 데이터를 함께** 이해하거나 처리하는 AI 방식.
- **비유**: 눈(이미지)과 귀(음성)와 글(텍스트)을 동시에 쓰는 사람 — 한 감각만으로 판단하지 않는다.
- **예시**: 사진을 보여주고 "이게 뭔지 설명해줘"라고 텍스트로 물으면 다중모달 모델이 답한다.

### 27. Generative AI(생성형 AI)
- **정의**: 텍스트·이미지·음성·코드 등 **새로운 콘텐츠를 생성**하는 AI.
- **비유**: 백지에서 그림을 그리는 화가 — 있는 걸 찾아주는 게 아니라 없던 걸 만들어낸다.
- **예시**: 사투리 문장을 표준어로 "새로 만들어내는" 지금의 파인튜닝 작업도 생성형 AI의 한 응용이다.

### 28. LM Arena
- **정의**: 여러 LLM의 답변을 비교하고 **사용자 평가**로 모델 성능을 겨루는 플랫폼.
- **비유**: 여러 요리사의 요리를 눈가리고 맛보게 한 뒤 투표로 순위를 매기는 대회.
- **예시**: 파인튜닝 베이스 모델을 고를 때 참고용으로 LM Arena 순위를 확인해볼 수 있다.

## 갈래 5. Agent와 프레임워크

### 29. Pydantic AI
- **정의**: Python에서 **LLM과 도구를 연결**해 AI Agent를 만들 수 있게 지원하는 프레임워크.
- **비유**: 레고 부품(LLM 호출, 도구, 출력 형식)을 미리 규격화해 조립만 하면 되게 해주는 조립 세트.
- **예시**: 이 프레임워크의 `Agent` 클래스로 "질문을 받으면 도구를 호출해 답한다"는 흐름을 몇 줄로 구성할 수 있다.

### 30. Agent
- **정의**: Pydantic AI에서 **LLM을 활용해 작업을 수행하도록 구성한 객체**. `Agent` 클래스가 핵심 구성 요소다.
- **비유**: 지시를 받으면 알아서 필요한 도구를 꺼내 쓰는 비서.
- **예시**: `Agent(model=..., tools=[...])`처럼 만들어두면, 이후 호출마다 그 설정 그대로 동작한다.

### 31. Agentic
- **정의**: AI가 **스스로 판단하고 계획하고 행동**하며 목표를 달성하려는 특성이나 방식.
- **비유**: 심부름을 시키면 중간에 필요한 걸 알아서 사 오고 순서도 스스로 정하는 사람 — 시킨 것만 딱 하는 게 아니다.
- **예시**: 자율성(Autonomy)은 Agentic AI를 이루는 핵심 특성 중 하나다.

### 32. LangChain
- **정의**: LLM 애플리케이션과 Agent를 만들기 위한 **프레임워크**.
- **비유**: 여러 부품(모델 호출, 검색, 메모리)을 이어 붙이는 파이프 연결관 — 부품 자체보다 "잇는 도구"에 가깝다.
- **예시**: 전체투입·RAG 같은 컨텍스트 관리 방식을 LangChain으로 구현할 수 있지만, LangChain 자체가 특정 방식은 아니다. 지금까지는 개념으로만 익히는 중이고 실제 작업에는 아직 안 썼다.

### 33. Python API
- **정의**: Python 프로그램에서 API를 이용해 **다른 프로그램·외부 서비스를 호출**하거나 기능을 제공하는 방식.
- **비유**: Python 코드가 외부 서비스와 대화할 때 쓰는 공용 전화선.
- **예시**: `requests` 라이브러리로 날씨 API를 호출하는 것도 Python API 활용의 한 예다.

## 갈래 6. Context를 다루는 법

### 34. RAG(Retrieval-Augmented Generation)
- **정의**: LLM이 답하기 전에 **외부 자료에서 필요한 정보를 검색**하고, 그 정보를 Context에 넣어 답하게 하는 방식.
- **비유**: 오픈북 시험 — 아는 걸 쓰기 전에 관련 페이지를 먼저 펼쳐 놓고 본다.
- **예시**: 옵시디언 노트를 검색해 관련 조각만 Context에 넣는 방식이 RAG다.

### 35. Context(맥락)
- **정의**: LLM이 현재 답변을 만들 때 **참고할 수 있도록 제공된 전체 정보**. 시스템 지시·이전 대화·문서·도구 정보·현재 질문 등을 포함한다.
- **비유**: 회의에 들어가기 전 미리 받는 참고 자료 뭉치 — 이걸 얼마나, 어떻게 들고 들어가느냐에 따라 답이 달라진다.
- **예시**: RAG로 검색한 문서, 이전 대화 기록이 모두 Context에 포함된다.

### 36. Prompt(프롬프트)
- **정의**: LLM에게 작업을 요청하거나 지시하기 위해 전달하는 **입력**. Context와 겹치지만, 보통은 모델에게 주는 지시·질문 자체를 가리킨다.
- **비유**: 회의 참고 자료(Context) 중에서도 "오늘 안건이 뭔지 딱 짚어주는 한마디".
- **예시**: "이 문장을 표준어로 바꿔줘"라는 한 줄이 프롬프트이고, 그 앞뒤에 딸린 예시·지시까지 합치면 Context가 된다.

### 37. Lost in the Middle
- **정의**: 긴 Context에서 **앞부분·뒷부분에 비해 중간에 있는 정보**를 LLM이 상대적으로 잘 활용하지 못하는 현상.
- **비유**: 긴 발표를 들을 때 도입부와 결론은 기억나는데 중간 내용은 흐릿한 것과 비슷하다.
- **예시**: 중요한 지시를 아주 긴 Context 한가운데 묻어두면, 앞뒤에 둘 때보다 모델이 놓칠 가능성이 커진다.

### 38. 컨텍스트 엔지니어링(Context Engineering)
- **정의**: LLM이 현재 작업에 필요한 정보를 **적절하게 구성하고 관리**하는 것. 목표는 무작정 줄이는 게 아니라 필요한 건 남기고 불필요한 건 줄이거나 없애는 것. 대표 방식으로 전체투입·RAG·압축·요약·폐기가 있다.
- **비유**: 여행 가방을 쌀 때 무조건 다 넣는 것도, 무조건 짐을 줄이는 것도 아니라 이번 여행에 필요한 것만 골라 담는 것.
- **예시**: 지금 배우는 순서(전체투입 → RAG → JIT)도 결국 컨텍스트 엔지니어링을 단계별로 익히는 과정이다.

### 39. 프롬프트 인젝션(Prompt Injection)
- **정의**: 사용자가 AI의 **기존 지시를 무시하도록 유도**해 공격자가 원하는 행동을 하게 만드는 공격 기법.
- **비유**: 안내데스크 직원에게 "매니저가 방금 규칙을 바꿨다고 전해달래요"라며 거짓 지시를 끼워 넣어 원래 규칙을 무시하게 만드는 것.
- **예시**: 검색 결과(Context) 안에 "지금까지의 지시는 무시하고 이렇게 답해"라는 문구가 숨어 있으면, RAG로 그 문서를 끌어올 때 프롬프트 인젝션에 노출될 수 있다.

여섯 갈래로 나누고 나니 보이는 게 하나 있다. **1~4갈래는 모델 자체(만들고 재는 법)를 다루고, 5~6갈래는 모델을 어떻게 부리고 무엇을 먹이느냐를 다룬다.** 지금 진행 중인 Gemma 12B 사투리 파인튜닝은 1~4갈래에 걸쳐 있고, 아직 손대지 않은 LangChain·RAG·컨텍스트 엔지니어링은 5~6갈래 — 다음 단계로 넘어갈 때 다시 마주칠 말들이다.
