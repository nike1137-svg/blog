> 관련 개념: [어텐션·트랜스포머 용어 정리](/blog/posts/terms-attention-transformer/)의 **토큰·LLM**, 그리고 지난주 [로컬 3B 실험](/blog/posts/too-many-tenants/)에서 본 "지어내기"가 여기서 다시 나온다.
{: .prompt-info }

지난주 글은 이렇게 끝났다. 내 리눅스 데스크탑은 방이 좁아 8B를 접었고, 큰 모델은 맥미니가 온 뒤로 미룬다고. 그런데 맥미니는 아직이다. 그래서 이번엔 **내 방을 넓히는 대신, 남의 방을 잠깐 빌리기로** 했다 — 구글 코랩이다. 결과부터 말하면, 방은 충분히 넓어서 7B가 잘 돌았다. 그런데 정작 그 안에 세운 챗봇이 **없는 동네를 자신 있게 지어냈다.**

> ⚠️ 보안상 터널 주소·토큰 같은 건 이 글에 담지 않는다. 과정과 배운 점만 남긴다.

## 1. 오늘 하려던 것

목표는 하나였다. **코랩 위에 Qwen 챗봇을 세우고, 그걸 내 브라우저가 아니라 바깥에서도 열 수 있게** 만드는 것. 흐름을 다섯 조각으로 나눠 진행했다.

1. **올라마 + ngrok 설치** — 올라마는 모델을 실행해 주는 틀, ngrok은 코랩 안에서 돌아가는 걸 바깥에서 접속할 수 있게 **임시 공개 주소(터널)**를 뚫어 주는 도구.
2. **Qwen 7B 내려받기** — 지난주 내 방에선 못 올렸던 크기다.
3. **올라마 서버 실행 + 터널 열기** — 모델 API를 터널로 바깥에 노출.
4. **Streamlit 챗봇 앱** — 대화창을 가진 웹 화면. 입력을 받아 올라마에 넘기고 답을 띄운다.
5. **챗봇도 터널로 공개** — 이제 링크만 있으면 누구 브라우저에서든 열린다.

여기서 코드는 대화형 AI(제미나이)와 함께 코랩에서 짰다. 이 글엔 코드를 통째로 옮기지 않고, **무엇을 왜 했는지**만 남긴다.

## 2. 남의 방을 빌린다는 것 — 코랩 + 터널

지난주와 이번의 차이가 여기서 갈린다.

- 지난주(로컬): 내 데스크탑 메모리가 상한이라 8B를 올리자 원래 살던 서비스가 쫓겨났다.
- 이번(코랩): 실행 환경 자체를 구글에서 빌리니, 7B 정도는 내 기기를 건드리지 않고 여유 있게 돌았다.

대신 새 숙제가 생겼다. 빌린 방은 **바깥에서 닿을 길이 없다**(코랩 안에 갇혀 있다). 그래서 ngrok으로 터널을 뚫어 임시 공개 주소를 만들었다. 이건 예전 새록이에서 클라우드플레어 터널로 "내 안의 서버를 바깥과 잇던" 것과 같은 발상이었다 — 도구만 달랐다.

## 3. 되긴 됐다 — 챗봇이 열렸다

설치 → 모델 다운로드 → 서버 → 터널까지 순서대로 돌아갔고, 마지막에 상태 진단 셀을 만들어 세 가지를 확인했다.

- ✅ 올라마 서버 프로세스: 실행 중
- ✅ 올라마 API 응답: 정상
- ✅ Qwen 모델 설치: 완료

터널 주소를 누르니 **"Qwen 3.5 Chatbot"** 화면이 브라우저에 떴다. 코랩에서 돌아가는 모델이 내 화면에서 대화로 응답하는 걸 보니, 다섯 조각이 하나로 이어진 게 실감 났다.

## 4. 그런데 — 없는 '남산구'를 지어냈다

여기서부터가 오늘의 진짜 소득이다. 내가 직접 질문을 던져 봤다.

- **"대한민국의 수도는?"** → "서울입니다." (정확)
- **"서울의 구는 몇 개야?"** → "약 25개 정도입니다. 이 수는 정확하지 않지만…" — **실제로 서울 자치구는 딱 25개**인데, 맞는 답을 두고도 자신 없어 했다.
- **"남산은 무슨 구지?"** → "**남산구**는 서울特別市의 한 개의 구로, 지번에는 '231'과 같이…" — **서울에 '남산구'는 없다.** 남산은 산 이름이고 중구·용산구에 걸쳐 있다. 없는 구를 만들고, 가짜 지번까지 붙이고, 한국어에 한자(特別市)를 섞었다.
- **"서울에 남산구는 없어"** (내가 정정) → "죄송합니다만… 제가 알고 있는 정보에서는 남산구这样一个存在입니다." — **정정해줘도 굽히지 않고** 오히려 우겼다. 또 중국어가 섞였다.

지난주 로컬 3B에서 본 장면("없는 사실을 그럴듯하게 지어냄", "한국어·영어가 섞임")이 **7B에서도, 그것도 더 완강하게** 반복됐다. 방을 키워도(모델을 키워도) 이 습성은 안 사라졌다. 작은~중간 모델은 **모른다고 말하는 대신 그럴듯하게 지어내는 쪽**으로 기운다는 걸, 이번엔 정정을 거부하는 모습까지 눈으로 봤다.

## 5. 판단 — 무엇을 배웠나

오늘 실습의 결론은 "챗봇을 띄웠다"가 아니라 **"띄운 챗봇을 어디까지 믿을지"** 쪽이었다.

- 파이프라인을 세우는 일(설치·서버·터널·앱)은 도구와 절차의 문제라, 순서대로 하면 됐다.
- 하지만 **모델의 답이 맞는지는 별개**다. 특히 로컬·소형 모델을 서비스에 쓸 땐, 그 답을 그대로 사용자에게 보여주면 안 된다는 걸 체감했다. 확인 장치(사실 검증·출처 표시)가 반드시 앞에 있어야 한다.

## 마무리 — AI가 한 일, 내가 판단한 일

| AI가 한 일 | 내가 판단한 일 |
|---|---|
| 코랩용 설치·서버·터널·Streamlit 코드 작성 | 내 방(로컬) 대신 **남의 방(코랩)을 빌리기로** 정한 것 |
| 설치 경로 탐색, 상태 진단 셀 구성 | 챗봇을 **내 질문(수도·구 개수·남산)으로 직접 검증**한 것 |
| 질문에 답을 생성 | 그 답 중 **'남산구'가 거짓임을 알아채고 정정**한 것 |
| 정정에도 우기는 응답을 내놓음 | 그걸 실패가 아니라 **"모델을 얼마나 믿을지"의 교훈으로** 삼은 것 |

도구가 챗봇을 빨리 세워 줄수록, 남는 몫은 **"그 챗봇의 말을 어디까지 신뢰할지"**를 정하는 쪽이었다.

## 다음 예고

빌린 방에선 7B가 잘 돌았지만 품질의 한계는 분명했다. 맥미니가 오면(통합 메모리) 더 큰 모델을 내 방에서 돌려, **크기를 키우면 이 '지어내기'가 줄어드는지**를 같은 질문으로 다시 확인해 볼 생각이다. 오늘이 "빌린 방에서 확인한 한계"였다면, 다음은 "내 방이 넓어진 뒤의 한계"가 될 것 같다.
